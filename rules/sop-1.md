# SOP 1：提示词 → 节拍 → 中文正文

内容边界见 `boundaries.md`，文风见 `style.md`，用词见 `wording.md`。另一套流程见 `sop-2.md`。

## 执行模式

### A 全量模式
1. **你给提示词** — 写到哪，范围就到哪。
2. **助手写节拍** — 根据提示词细化剧情走向、情绪张力与动作节拍，写入该故事目录下的 `beats.md`，请你审阅。
3. **确认后落盘正文** — 节拍审阅确认后，助手严格在已定节拍范围内发挥细节，内置 `wording.md` 硬禁与 `style.md` 去形容词化负向约束，直接写入当前章节 `chapters/chxx.md`。

### B 分批模式
1. 节拍总体确认后，助手按 **SEC 或节拍组** 逐批落盘。
2. 每轮开始前明确本轮覆盖范围，例如“节拍 4–5 / SEC 4–5”。
3. 未指定范围时，默认一次写 **1–2 个 SEC**，不把整条主线一口气写完。
4. 每轮只汇报写入范围、行号链接与下一轮可接续位置，不粘贴正文原文。

### C 免审模式
1. 用户明确说“不审 / 直接写”时，助手确认本轮范围后直接落盘正文。
2. 免审只跳过中间确认环节，**不表示可以超出节拍范围或放宽边界**。
3. 落盘后照常汇报行号范围，不输出自检过程。

## 范围对齐与执行边界

- **只做要求做的，不做未要求做的**：
  - 在已审节拍范围内，可以充分发挥动作、心理、环境与感官细节。
  - **严禁超出节拍范围**：节拍未给到的剧情转折、玩法、新登场人物，正文绝不擅自抢跑或增补。
  - 除非你明确要求，助手不主动生成、更新或推荐 `inspiration.md`。
- 分批写作时，节拍范围由用户指定或按 SEC 自然划分；没有明确指示时助手应先用一句话确认范围再动笔。

## 正文落盘与 SEC 规则

- **严禁 YAML**：正文文件（`chapters/chxx.md`）**禁止包含任何 YAML frontmatter / 元数据块**，直接从正文（或 SEC 标记）起笔。
- **是否分 SEC 以当前故事/用户指示为准**。若分 SEC：
  - 按 `rules/style.md` 规范，SEC 标识统一采用居中、Serif 衬线体、字号大于正文的纯数字格式（`<p align="center" style="font-family: serif; font-size: 1.4em;">1</p>`），不展示中文小节名。
  - 每个章节内 SEC 编号从 `1` 开始；后续接写时从当前章节已有最大 SEC 编号继续。
  - 分批写作可以“一个 SEC”或“连续多个 SEC”为一次落盘单位；SEC 内部保持连续推进。
- 一章写满或你明确要求再开下一章文件（`ch01.md` → `ch02.md` …）。

## 节拍文件管理

- `beats.md` 保存当前故事的节拍规划与推进进度。
- 分批写作时，不需要每轮重写整个 `beats.md`。
- 剧情方向变化时，同步更新 `worldview.md` 与 `beats.md` 中的已完成/待写状态。
- 已完成的节拍可标注为“已完成”；未写的保留为“待写”。

## 对话纪律（0 额外 Token 消耗）

- **除非你明确要求**，对话里 **永远不要粘贴正文原文**。
- **严禁输出自检过程**：严禁在对话中输出词汇合规分析、审查过程或字词清单，保持 0 额外 Token 消耗。
- **汇报必须标明行号范围**：每次写入或修改正文落盘后，汇报必须明确标明本次修改/写入的具体行号区间（如 `[ch01.md#L445-L515](file:///D:/VSCode/DayDream/characters/creator/episodes/chapters/ch01.md#L445-L515)`），以便你快速定位查看。
- 只汇报已完成的动作、本轮覆盖范围与对应行号链接。
- 请你直接打开对应章节文件查看。

## Git 纪律

- **默认不 commit**：正文落盘及日常文件修改后，助手禁止自行执行 `git commit`。
- 只有在你明确下达提交要求（如「提交修改」、「commit」）时，才执行 git 提交。

## 工具脚本（0-Token 本地按需执行）

- **字数统计**：仓库在 `scripts/count-chars.ps1` 维护汉字字数统计脚本。**当且仅当你明确要求统计字数时**运行并汇报。
- **用词静态扫描**：仓库在 `scripts/check-wording.ps1` 维护硬禁词 0-Token 静态扫描脚本。**当且仅当你明确要求检查用词时**运行并汇报；平时依靠模型内置约束，不主动执行。
