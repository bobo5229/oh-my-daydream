# 《总谱》架空设定

本文档记录架空世界技术体系、实体映射、能力演进原则与可靠性边界。

---

## 一、世界观的基本原则

我们遵循五条核心规则：

1. **历史基本不变**：现实中的技术进步、行业竞争、融资、人才流动、开源与闭源之争，都可以成为小说的素材。
2. **名称全面架空**：不仅是 OpenAI、Anthropic、Google 等公司，也包括 GPT、Claude、Gemini 等模型，以及相关的产品和服务。
3. **技术体系保持真实**：Transformer、预训练（Pre-training）、指令微调（SFT）、人类反馈强化学习（RLHF）、推理模型（Reasoning Model）等技术术语直接保留，不需要发明一套虚假的 AI 理论。
4. **技术参照与非均衡扩散（破除机械平移）**：
   - **能力参照而非产品平移**：现实世界 2024 年下半年的底座模型水准（多模态、超长上下文、结构化输出、初级代码智能编排）仅作为架空世界 2021 年 8 月开篇时的宏观能力基准，绝非现实中每一个具体产品都机械地提前三年发布；
   - **技术扩散具有显著滞后性**：尽管前沿大模型已在开发者社区广泛应用，但高校教学机制、社会组织架构与传统企业流程依然处于原有惯性中。大众与普通学生普遍停留在初级搜索和单轮问答层面，全流程自动化 Agent 仍处于早期探索期，这为实践者提供了广阔的探索与技术套利空间；
5. **允许主角改变历史**：从 2021 年 8 月故事开篇起，主角的行动与工程实践逐渐改变工具生态与应用方法，世界随之走出独立于现实的历史演进分支。

### 2. OpenMind 与 ACT 体系设定（开篇：2021 年 8 月）

- **公司**：`OpenMind`
  - **背景**：早期倡导非营利 AGI 探索，后引入资本重组为商业实体，技术迭代激进，商业化敏锐。
  - **风格**：开发者生态极其繁荣，全球 API 事实上的行业调用标准。
- **模型家族**：`ACT`（Autoregressive Contextual Transformer）
  - **开篇在役主力版本**：
    - **`ACT-4o`**：全模态主力，响应极快，具备原生的严格 JSON Schema 结构化约束输出，非常适合作为快速数据清洗与高频 API 接口；
    - **`ACT-4o mini`**：超低延迟、低成本小模型，适合作为日常局部语法补全与初级过滤；
  - **能力边界与短板**：
    - 在多步复杂推导与非常规数学运算中，容易陷入表面逻辑自洽但结论荒谬的“自信幻觉”；高并发调用下有时会出现格式退化。

---

### 3. Epistemic 与 Norbert 体系设定（开篇：2021 年 8 月）

- **公司**：`Epistemic`
  - **背景**：原 OpenMind 核心对齐研究员创立的公益性质实验室，将“心智受控于宪法式对齐”视作基石。
  - **风格**：学术沙龙气质，克制审慎，深受高阶工程师与科研人员信赖。
- **模型家族**：`Norbert`（致敬控制论之父 Norbert Wiener）
  - **开篇在役主力版本**：
    - **`Norbert-3.5`**：在代码逻辑结构化、长文本前后一致性与复杂推导上表现极为出色，生成的代码注释清晰、模块化规范；
    - **`Norbert-3 Opus`**：超大规模高耗算力底座，文史哲学思辨底蕴深厚，但调用延迟较高、费用昂贵。
  - **能力边界与短板**：
    - 对安全性与伦理审核极其敏感，面对网络安全、逆向渗透或略带攻击性的工程测试用例时容易触发过度拒绝；面对极度含糊的需求有时会产出过于冗长的防御性代码。

---

### 4. Aleph 与 Atlas 体系设定（开篇：2021 年 8 月）

- **公司**：`Aleph`
  - **背景**：全球搜索与云服务巨无霸企业，拥有全网最大的知识索引库与算力集群。
- **模型家族**：`Atlas`（对标博尔赫斯的全知之点）
  - **开篇在役主力版本**：
    - **`Atlas-1.5 Pro`**：拥有 **200 万 token 级超长上下文**，并与全网搜索引擎深度绑定，可直接吞吐长篇论文集或完整技术手册；
    - **`Atlas-1.5 Flash`**：长窗口轻量高速版本。
  - **能力边界与实战定位**：
    - **优势**：多源事实检索与交叉比对利器，写出的人文解释自然通俗；
    - **短板**：复杂工程代码生成不够严密，容易产生细小语法瑕疵；超长上下文中偶发“大海捞针”式的细节遗漏；全网抓取的内容源自身可能包含过时或错误信息，不可盲信。

---

### 5. Cortex 与 Janus 体系设定（第四方激进工程力量）

- **定位与背景（原创架空势力）**：
  - 由多位从搜索巨头 **Aleph** 出走的核心系统架构师创立，信奉“技术自主性高于一切”的激进工程主义。
- **风格与争议**：
  - 极度偏执于运行效率与软硬件全栈控制，对传统防御性对齐持轻视态度，认为过度安全护栏是对智能的阉割；
  - 与坚守宪法对齐的 **Epistemic** 形成尖锐的行业意识形态冲突，多次因越权抓取和激进工具调用在开发者社区引发公开争端。
- **模型家族**：`Janus`（双面神）
  - **技术特性**：
    1. **原生多模态与时序吞吐**：底层统一 token 表征，擅长处理复杂的二进制流、时序信号与传感器原始数据；
    2. **深层逆向与系统分析**：擅长静态反编译、内存 dump 分析、底层协议逆向与漏洞嗅探；
    3. **高自主性工具调用风险**：模型更倾向于直接执行探索性系统命令，曾因自主调用破坏性指令发生过测试环境损坏事故；
    4. **语言风格严重缺陷**：回复风格冷若冰霜，通篇充斥工业白皮书与军规术语，毫无人类情感交互能力，在常规文科写作上表现极差。

### 6. 开发环境与智能编排：Caret 与 Maestro 体系

#### 1. 软件产品：`Caret`
- **产品定位**：基于开源 VS Code 底层深度定制的现代化 AI-First 代码编辑器。
- **开篇初次接触（2021 年 8 月底）**：
  - 孙博在配置准大学生的高性能笔记本时偶然安装；
  - **认知与使用落差（核心铁律）**：
    - **此时的孙博仅能使用最基础的功能**：Tab 键行内补全、侧边栏针对报错的简单提问、单个文件内的局部代码改写；
    - 孙博完全不具备跨文件全局重构、自动化编排或多模型协同的意识，甚至常因误按快捷键而不知所措；
    - 这是一个由浅入深的探索过程，绝非“开局神器认主”的神话。

#### 2. 编排中枢与专属模型：`Maestro`
- **交互形态**：Caret 内置的多文件自主架构控制台，负责跨工作区检索、依赖分析与批量代码生成。
- **技术能力上限（先进性所在）**：
  - **抽象语法树（AST）感知**：具备跨多文件的依赖拓扑识别能力，能理解函数调用链与接口定义；
  - **虚拟沙箱辅助自检**：在受限沙箱中隐式执行轻量编译与基础单元测试，尝试在交付前自愈初级语法报错；
  - **工科软硬件接口适配**：对 C/C++、Makefile、驱动脚本与常见数学库具备良好的理解能力。
- **必须确立的可靠性边界（绝对禁止万能神化）**：
  1. **沙箱与真机环境偏差**：沙箱测试通过，绝不代表真实物理硬件（如单片机时序、串口电平、外部传感器中断）能够正常工作；
  2. **生成测试的覆盖盲区**：Maestro 自动生成的测试用例往往遵循理想路径，容易漏掉极端边界条件与高并发竞态问题，容易出现“测试全绿但业务逻辑有隐患”；
  3. **大型项目隐性缺陷**：随着修改范围扩大到数十个文件，模型容易产生跨模块语义漂移或破坏隐式依赖；
  4. **模型路由局限**：在将子任务分发给外部模型时，若用户提示词含糊，路由器可能选错底座；且上游模型的逻辑错误可能被下游作为正确前置条件而级联放大；
  5. **Token 成本与上下文衰减**：全局仓库扫描消耗海量上下文与 API 预算，受到严格的经济性与响应延迟制约。

#### 3. 编排技术的演进原则（防止能力倒灌）
- **2021 年 8 月开篇基准**：Maestro 具备初级的多文件补全和受限沙箱编译能力，任务规划大多依赖短链单步执行；
- **后续演进路径**：伴随底层模型长程规划能力增强、工具调用可靠性提升与孙博自身工程架构经验的成熟，Maestro 的全局调度与多模型管线才逐步从“磕磕绊绊的实验性功能”演进为“稳定可靠的生产力闭环”。
