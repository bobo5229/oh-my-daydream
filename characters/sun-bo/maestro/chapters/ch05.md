# 第五章｜一封发出去的邮件

三月初回到学校时，西安的风还是冷的。

拖着箱子走进六号楼，我先在宿舍门口等了半天，才等到里面有人把插着耳机的脑袋从屏幕后面抬起来。寒假里攒着没洗的床单被套、从家里带来的零食和一堆快递盒子，很快把几个人的床铺旁边重新堆满。开学头两天除了去领新课表，我基本上都在收拾东西，晚上继续打《方块纪元》，那台矿石加工厂在游戏里倒是一直运转得挺好。

手机里隔三岔五还会跳出 Gulu 的评论，有人问 Nexalogic 的新版是不是已经修好，有人顺手在视频底下贴了官方 Release Notes。我看见熟悉的 GitHub 账号名，还是会多瞄两眼，不过新鲜劲儿已经没刚合并那两天那么足了。

周日晚上，我对着课程表发愁。第二学期的课排得不算少，有几门名字看上去比上学期难得多。顺手翻到浏览器收藏夹，一个假期没动的学校官网躺在那里。我忽然想起期末考完后，计算机学院那个年轻老师说过的话。

“大创、萌创……有兴趣就来看看。”

寒假一直在玩游戏，也没真想过去找他。倒不是觉得人家不靠谱，只是我一个学海洋工程的，真去了计算机学院的项目组，能帮上什么忙也说不准。再说，我上学期做得最像样的两个东西，一个是借助 Agent 写的迷宫，另一个是给游戏模组修了一根管道，离真正搞计算机研究差了不知道多远。

我关掉课程表，打开自己学院的网站。

导航栏里有个“师资队伍”。点进去是一长串老师的名字、职称、研究方向和邮箱。网页做得有些年头了，部分照片加载半天才出来。我顺着“水声”“海洋信息”一类关键词翻，陆续看到水下声传播、水声信号处理、水声通信、声学测量这些词。

“声源定位”四个字让我停了一下。

这几个字至少能看懂：听声音，判断它从哪儿来。可往下读，什么到达时间差、阵列几何、多径传播，很快又不大明白了。

我把其中一位老师主页上的研究方向复制到网页端的 Atlas，问得很直白：

“我是海洋工程类大一学生，下学期想找个本科生科创项目。这几个研究方向都是什么意思？有没有适合现在这种基础的人做的事情？不用写得太专业。”

Atlas IV 是二月刚推出的型号。寒假末尾我在技术社区看过不少讨论，大家吵归吵，有件事说得倒很一致：Aleph 这次的新模型读大段资料、整理论文和写文章特别厉害，做科研辅助也很受关注。GRM-4.1 则在数学推理和编程上更猛一些；Norbert 配合 Kybernetes 做工程，我自己已经领教过了。至于到底谁全面压过谁，我没有认真研究那些榜单，手头有事时能挑个合适的用就行。

一月底关掉 Epistemic Fellow 的续费后，二月我就没再掏钱。二十美元一个月，换成生活费里的一百多块，我还没阔到能把几家的会员全开着。眼前只是查老师、了解研究方向，先用 Atlas 网页端能用的额度看看就好。

Atlas 没有一下扔来满屏公式，而是把几个方向拆开解释，还提醒我，本科生项目往往要看老师手里有什么现成设备、数据以及愿意让学生参与的工作。它拿“用多个水听器估计水中声源位置”举例，说可以从水槽里的简单验证做起，但测量同步和水面、槽壁反射都会影响结果。

我看到一半，忽然想起在游戏里隔着区块接管道的那几天。不是说两件事有多像，只是都有种“看起来很简单，真正做时全是条件”的味道。

我又点开其他几位老师的主页，来回筛了一个多小时。有的研究方向离我现在学的东西实在太远，有的页面几年没更新。我把觉得有兴趣的名字、邮箱和方向记在一张表里，最后选了三位老师准备问问。

发邮件这事反倒让我磨蹭了很久。

我先让 Atlas 帮我起草。它给出的第一版客气得有点过头，一开头就是对老师研究工作的仰慕，后面还说我对水声信号处理有“持续而深入的理解”。我看得脸都有点热。这学期专业基础课还没上几节，哪来的深入理解？

我把那几句删了，改成实话：我是本院大一学生，对水声方向感兴趣，上学期学了 C 语言，平时爱折腾软件，寒假还参与过一次开源项目的 Bug 修复；想问老师有没有面向低年级本科生的科创机会，自己愿意从资料整理和基础工作做起。

又犹豫了一下，我没把“参与开源项目”写得太威风，后面补上是借助 AI 工具完成的。修复虽然最终合并了，但我知道那些 Java 代码自己真写不出来。

三个邮件地址检查了两遍，鼠标移到发送按钮上时，我居然比向 Nexalogic 提 PR 还紧张。给陌生维护者发 Issue，好歹是在说一个确实存在的 Bug；给老师发邮件，却像是在问人家愿不愿意让我这个什么都不会的新生去占一个位置。

我干脆一口气点了发送，然后合上电脑出去吃晚饭。

第一封邮件当天没有回。第二位老师隔了两天礼貌地告诉我，现阶段课题组暂时不安排大一学生参加。第三封等到周四晚上终于有了回复，内容不长：

“孙博同学，你好。我们近期正在组织一项本科生科创项目申报，方向是小型水听器阵列的水下声源定位与实验验证。如有兴趣，可以周五下午到实验室了解一下。项目还在申报阶段，不保证最终获批。”

我对着那段话看了好几遍，才把邮件转进收藏夹。

周五下午，我在教学楼和实验楼之间绕了两圈，最后跟着墙上的房间号找到实验室。门边贴着一张褪色的设备管理表，里面一位学长正在给电脑接线，桌上放着几根线缆和灰色的金属盒子，角落里还有一个盖着塑料布的长方形水槽。

回邮件的老师正在看材料，见我来了便让我坐下。他问了几句课程情况和兴趣，又翻看了我手机里那条已经合并的 GitHub PR。

“你主要负责复现、测试，代码修改靠 Agent 帮忙，是吧？”

“对。我自己 Java 不行，能看懂一点问题在哪儿，但具体怎么改基本都是工具干的。”

他点点头，没有觉得这件事多么了不得，也没有追着问我用了哪款模型。

“肯动手挺好。我们这个项目跟你之前做的东西不大一样，先别急着写程序。”

老师从桌上拿起一份打印好的项目简介，简单说明他们准备做一个适用于小型实验水槽的水下声源定位原型：布置几只水听器接收测试声源的信号，利用到达时间差估计位置，再和已知位置对照，看哪些条件下误差比较大。实验室有部分现成设备，学生主要做方案整理、基础实现和实验验证，具体工作要看立项和分工情况。

我听懂了大半，剩下那小半只好在纸上记下来。比如老师说到“同步采样”，我大概知道各路信号得对齐，但具体为什么差一点就会影响定位，心里并没有数。

当天下午还有几位准备一起申报的学生过来。有人已经帮老师做过些基础实验，有人熟悉文档格式，我是刚来的那个。老师没有把我当成已经确定的项目骨干，只问我愿不愿意先和大家一起把立项材料准备出来。

我当然说愿意。

我们把一份往年的申报模板投到屏幕上，研究背景、立项依据、项目目标、研究内容、实施方案、进度安排、经费预算，每一项下面都是空白的填写框。有人小声说这比期末课设的报告还麻烦。

老师让大家按已有资料先分头准备，技术路线和设备条件由熟悉实验室的同学起草，我负责“研究背景与项目意义”的初稿，顺便整理一份相关文献清单。最后整合由团队再一起做。

这个安排让我松了口气。至少没有一上来让我画阵列、推公式。

拿到的资料里有几份中文论文、一份设备简表，还有老师标注过的几页笔记。我回宿舍后把文件分类放好，先逐篇粗看了一遍。很多段落看得很慢，尤其那些带符号的推导。我一边看一边把不理解的词记下来，再分批交给 Atlas，让它解释这些概念在本项目里的作用。

直接让它生成“国内外研究现状”倒是很容易，出来的东西还很像那么回事：水声定位技术应用广泛、研究意义重大、国内外学者开展了大量工作……但多看两遍就发现，换成任何一个水声项目都能这么写。它还顺手列了几个我没在资料里见过的论文题目。

我没敢直接贴进去。

上次修模组时维护者一条条追问版本和复现条件的经历还在脑子里。老师以后要是问“这篇文献在哪儿”，我总不能回答“AI 说有”。

我重新给 Atlas 说明范围：只根据我提供的文献和老师的项目简介整理观点，引用对应原文位置，找不到出处就标注待核实；不自己补论文，也别把项目写成解决水下定位所有难题的革命性方案。

这次材料终于实在了不少。

我先列出几条自己看得懂的脉络：水下声源定位为什么需要多个接收点；实验环境与信号传播条件会怎样影响定位结果；现有教学和入门实验里，搭建、采集和结果对照有哪些实际难处。再把老师项目简介里的目标单独拎出来，强调这次只做**可控条件下的小型原型和误差验证**，而不是宣称解决复杂海洋环境下的精确定位。

Atlas 很擅长把零散材料重新组织成顺畅的段落。我删掉它那些太满的形容词，换掉几处我不敢确认的专业判断，把来源不明的句子先留空。写到一半，我还有点烦躁：明明已经有一段看着挺像正式材料的文字了，为什么还要逐条回去找出处？

但一想到这份申请书不是只有我自己看，又只能耐着性子翻文件。

忙了两个晚上，初稿总算有了样子。大概是我上学期交过的所有文档里，最不像临时赶出来的一份。

周一晚上，大家把各自负责的部分发到共享文件夹。有人写得很扎实，但开头直接堆了几段定义；有人把“预计达到的效果”写得像已经完成实验；还有几段从不同资料摘来的文字，连同一个设备的叫法都不一样。

我自己的那一节看起来确实顺一点，标题下面先说问题，再解释现有方法和限制，最后引出项目准备完成的东西。要说这些文字全是我自己一句句琢磨出来的，那肯定不是。可哪些内容留、哪些要删、哪些得回原文找证据，我已经来回改了不少遍。

第二天下午，老师召集我们对初稿。

他从第一页往后看，边看边用红笔做记号。设备清单有几项要再确认，进度安排过于乐观，技术路线里有个步骤写得含糊。几位同学轮流解释自己负责的部分，我坐在一边，心里盘算着自己的那节会被圈掉多少。

老师翻到“研究背景与项目意义”，读了大半页，笔尖停了下来。

“这一段是谁写的？”

“我。”我坐直了一点。

“组织得还可以。”他又往下看了几行，“问题从哪儿来、为什么做小型验证、打算解决什么，写得比较清楚。前面几段有的地方还是材料堆材料，这一段至少能让不熟悉项目的人顺着看下去。”

我心里忽然有点高兴，但他很快又指着一处问：“这里说小型水槽的反射会影响到达时间差估计，你是从哪篇材料里整理的？”

我翻开笔记本，找到自己标好的文件名和页码。那篇文章有示意图，我把图旁边的说明指给他看，又老实补了一句：“具体怎么影响，我还没有完全弄懂，只知道这会是实验里需要注意的问题。”

“嗯，别把没弄懂的东西写成已经论证过的结论。”老师说着，在那一段旁边写下“表述再收一点”，然后把文件翻回前面，“其他几节也可以参照这个结构，不要光是罗列材料。”

他抬头看了我一眼：“你这部分整理得不错。后面大家修改完，你帮着看看全文措辞和术语能不能统一，技术内容不确定的就找负责那一块的同学确认。”

“好。”

会议继续往下开。我把老师批注的地方记下来，又听其他人讨论设备和经费。那些具体问题我大多插不上话，尤其有人说到多通道采集设备的同步精度时，我连应该问什么都不知道。

不过轮到研究背景那一页，大家已经开始拿我的初稿作参考。

散会后，走廊里有人拍了拍我的肩：“你那部分写得是真顺，回头把格式也教教我。”

我笑了笑，说其实改了好几轮，还借助 Atlas 帮忙整理。

“怪不得。”他看着我，又补了一句，“不过你那几篇参考文献标得挺全，我之前让 AI 写的时候老给我瞎编。”

我点点头。这一块自己确实花了不少时间。

晚上回到宿舍，我在电脑上打开申请书，把老师说要修改的那一句先圈起来。共享文件夹里其他几位同学也陆续传来了新版本，等着后面再合到一起。

桌面右下角还有一个早已过期的 Epistemic Fellow 会员提示。我看了它一眼，没去点续费。眼下只是看资料、写申报书，Atlas 已经帮了不少忙；真到要动手做项目时，再看看用什么工具划算。

我把那份写满批注的初稿另存成新版本，合上笔记本，先去食堂吃饭。

申请书还没交，项目能不能立项也没有准信。不过至少，我已经在这份材料里做出了一点能让老师用得上的东西。
