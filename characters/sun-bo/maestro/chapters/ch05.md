# 第五章｜一封发出去的邮件

三月初回到学校时，西安的风还是冷的。

拖着箱子走进六号楼，我先在宿舍门口等了半天，才等到里面有人把插着耳机的脑袋从屏幕后面抬起来。寒假里攒着没洗的床单被套、从家里带来的零食和一堆快递盒子，很快把几个人的床铺旁边重新堆满。开学头两天除了去领新课表，我基本上都在收拾东西，晚上继续打《方块纪元》，那台矿石加工厂在游戏里倒是一直运转得挺好。

手机里隔三岔五还会跳出 Gulu 的评论，有人问 Nexalogic 的新版是不是已经修好，有人顺手在视频底下贴了官方 Release Notes。我看见熟悉的 GitHub 账号名，还是会多瞄两眼，不过新鲜劲儿已经没刚合并那两天那么足了。

周日晚上，我对着课程表发愁。第二学期的课排得不算少，有几门名字看上去比上学期难得多。顺手翻到浏览器收藏夹，一个假期没动的学校官网躺在那里。我忽然想起期末考完后，计算机学院那个年轻老师说过的话。

「大创、萌创……有兴趣就来看看。」

寒假光顾着玩游戏，没真动过找他的念头。我学的是海洋工程，真跑去计算机学院的项目组，能干什么心里完全没底。更何况我上学期做得最像样的两样东西，一个是借助 Agent 做出来的图形界面迷宫，另一个是给游戏模组修了根管道，离正经的计算机研究差了十万八千里。

我关掉课程表，打开自己学院的网站。

导航栏里有个「师资队伍」。点进去是一长串老师的名字、职称、研究方向和邮箱。网页有些年头了，部分照片加载半天才慢吞吞刷出来。我顺着「水声」「海洋信息」一类关键词翻，陆续看到水下声传播、水声信号处理、水声通信、声学测量这些词。

「声源定位」四个字让我停了一下。

这几个字至少能看懂：听声音，判断它从哪儿来。可往下读，什么到达时间差、阵列几何、多径传播，很快又不大明白了。

我把其中一位老师主页上的研究方向复制到网页端的 Atlas，问得很直白：

「我是海洋工程类大一学生，下学期想找个本科生科创项目。这几个研究方向都是什么意思？有没有适合现在这种基础的人做的事情？不用写得太专业。」

Atlas IV 是二月刚推出的型号。寒假末尾我在技术社区看过不少讨论，大家吵归吵，有件事说得倒很一致：Aleph 这次的新模型读大段资料、整理论文和写文章特别厉害，做科研辅助也很受关注。GRM-4.1 则在数学推理和编程上更猛一些；Norbert 配合 Kybernetes 做工程，我自己已经领教过了。至于到底谁全面压过谁，我没有认真研究那些榜单，手头有事时能挑个合适的用就行。

一月底关掉 Epistemic Fellow 的续费后，二月我就没再掏钱。二十美元一个月，换成生活费里的一百多块，我还没阔到能把几家的会员全开着。眼前只是查老师、了解研究方向，先用 Atlas 网页端能用的额度看看就好。

Atlas 避开了大堆复杂的数学公式，直接把这几个方向拆开成平白解释，还提醒我，本科生项目往往要看老师手里有什么现成设备、数据以及愿意让学生参与的工作。它拿「用多个水听器估计水中声源位置」举例，说可以从水槽里的简单验证做起，但测量同步和水面、槽壁反射都会影响结果。

我看到一半，忽然想起在游戏里隔着区块接管道的那几天。两件事路数不同，底下那种「看起来很简单、做起来全是边界条件」的劲头，倒是一模一样。

我顺着其他几位老师的主页挨个筛选，来回翻了一个多小时。有的研究方向离我现在学的东西实在太远，有的页面几年没更新。我把觉得有兴趣的名字、邮箱和方向记在便签里，最后挑了三位老师准备问问。

发邮件这事反倒让我磨蹭了很久。

我先让 Atlas 帮我起草。它给出的第一版客气得有点过头，一开头就是对老师研究工作的仰慕，后面还说我对水声信号处理有「持续而深入的理解」。我看得脸都有点热。这学期专业基础课还没上几节，哪来的深入理解？

我把那几句全删了，换成大实话：我是本院海洋工程类大一学生，入学后对水声方向越来越感兴趣，尤其是老师主页上提到的水下声源定位。虽然专业课才刚开始接触，阵列和声传播的原理也还不懂，但我想知道真实的水声实验是怎么做的，能不能从读资料、协助实验这些基础事情学起。

写完又读了一遍，把话说清楚就够了。邮件不是个人简历，用不着把寒假折腾游戏模组的事全塞进去。

三个邮件地址核对了两次，鼠标移到发送按钮上时，我心里甚至比当初向 Nexalogic 提 PR 还发紧。给陌生维护者发 Issue，好歹是在讲一个客观存在的 Bug；给老师发邮件，却像是在问人家愿不愿意让我这个两手空空的新生去占个位置。

我干脆闭眼点了发送，合上电脑直接出门吃晚饭。

第一封邮件当天没有动静。第二位老师隔了两天礼貌地回复，现阶段课题组暂时不安排大一学生参加。第三封等到周四晚上终于有了回音，字数不多：

「孙博同学，你好。我们近期正在组织一项本科生科创项目申报，方向是小型水听器阵列的水下声源定位与实验验证。如有兴趣，可以周五下午到实验室了解一下。项目还在申报阶段，不保证最终获批。」

我盯着屏幕看了好几遍，把邮件仔细归进了星标文件夹。

周五下午，我在教学楼和实验楼之间绕了两圈，顺着墙上的房间号找到实验室。门边贴着一张褪色的设备管理表，里面一位学长正蹲在桌旁给电脑接线，台面上散着几根线缆和灰色的金属采集箱，房间角落里还摆着一个罩着塑料布的长方形水槽。

回邮件的老师正在看材料，见我进来便指了指旁边的椅子让我坐。他随口问了几句我这学期选的课，又问我怎么想起联系水声方向。

「在学院网站上看了几个研究方向，声源定位这个最想了解。」我想了想，老老实实补了一句，「看介绍好像能靠几只水听器判断声音从哪里来，觉得挺有意思。不过那些到达时间差、阵列排布什么的，我现在还没学过。」

老师点了点头：「大一还没学到这些很正常。愿意提前接触是好事，但我们做实验，不能只看最后算出一个位置，还得弄清楚测的是什么、条件靠不靠谱。」

我赶紧把这句记在随身带的本子上。老师没问我会用什么编程工具，我也没主动提；眼下连项目本身是什么阵仗都还没摸清，没必要瞎吹。

老师从桌上拿起一份打印好的项目简介，简单讲了讲他们的设想：做一个适用于小型实验水槽的水下声源定位原型，在水里布置几只水听器接收测试声源的信号，利用到达时间差估计位置，再和实际已知的位置做比对，摸清楚哪些条件下误差偏大。实验室有部分现成硬件，学生主要做方案梳理、基础算法跑通和实验验证，具体任务看立项和人员分工。

我勉强听懂了大半，剩下听不懂的先囫囵记在纸上。比如老师提到「同步采样」，我大概明白各路信号时序必须对齐，但具体差上几微秒会导致定位偏出去多远，脑子里完全没概念。

当天下午还有两三个准备一起申报的同学过来。有人早就在实验室帮着打下手，有人熟悉申报书的格式规范，只有我是头一回进门的新人。老师没把我当成钦定的项目主力，只问我愿不愿意先和大家一起把立项申报书攒出来。

我立刻应了下来。

往年的申报模板投在会议室白墙上，研究背景、立项依据、项目目标、研究内容、实施方案、进度安排、经费预算，每一栏底下全是空白方框。有人小声嘀咕这比期末课设报告折腾人得多。

老师让大家按手头现有的资料分头动笔，技术路线和设备条件由熟悉实验室的同学起草，我负责「研究背景与项目意义」的初稿，顺带把相关文献清单整理出来。最后整合由团队碰头敲定。

这个差事让我暗暗松了口气。至少没一上来逼着我推公式、算坐标。

分给我的资料里有几份中文学报论文、一份设备参数简表，还有老师批注过的几页实验手稿。回宿舍后我把文件理顺，挨个粗读了一遍。那些密密麻麻带下标的公式看得很费劲，遇到卡壳的概念我便随手记下来，分批扔给 Atlas，让它解释这些名词在小型水槽实验里究竟指什么。

直接让它生成「国内外研究现状」倒是快得很，几秒钟就吐出一篇人模狗样的套话：什么水声定位应用广泛、意义重大、国内外团队开展了大量卓有成效的研究……可多扫两眼就能看出来，换成任意一个水声课题套进去都严丝合缝，甚至还顺嘴胡诌了几个原文里根本不存在的论文题目。

我没敢直接往申请书里贴。

寒假给 Nexalogic 提 PR 时，海外维护者追着问复现环境和断言条件的场面还历历在目。老师回头要是随口问一句「这篇文献引用自哪本刊物」，我总不能跟人家说「这是大模型脑补出来的」。

我重新在输入框里跟 Atlas 交代清楚：只准按我给的文献和项目简介来整理，每一句话都要能在资料里找到出处；找不到就老实标上待核实，别自己瞎编论文名字，也别把一个小实验吹得天花乱坠。

约束加上之后，出来的东西总算实在了些。

我按自己能看明白的几样事情排了排：为什么水下定位要放好几个水听器，水槽壁反射和测量同步可能会带来什么影响，还有平时做这种小实验在采集和对比数据时有哪些麻烦。再把老师写的简介放进去，把目标老老实实定在小型原型和误差验证上，不扯那些复杂海洋环境的大词。

大模型理材料确实快，顺着读下来挺像那么回事。不过里面那些太满的形容词还是得我动手删，碰到自己吃不准的说法，也得老老实实空着或者翻原文。整理到后半夜，我难免有些发烦：明明放一段套话也能交差，何必非得逐条回去找出处？

可这份材料好几个人都得过目，最后还要送去院里评审，我只能耐着性子把文献页码一个个标上去。

熬了两个晚上，初稿总算成型了。这是我进大学以来，写得最不像临时抱佛脚的一份材料。

周一晚上，大家把各自的模块扔进了共享文件夹。有人写得扎实，但开头劈头盖脸就是好几段抽象定义；有人把「预期成果」吹得像是实验早就跑通了一样；还有几节是从不同文献里东拼西凑摘出来的，同一台仪器在前后页里的叫法都打架。

我负责的那一节读起来顺当得多，标题底下摆出实际工程问题，再交代常规做法与现实限制，最后顺理成章引出项目要做的事。虽然底稿是模型帮忙搭的骨架，但哪些内容该留、哪些话该砍、哪些论断必须回原文核验，我实打实改了好几轮。

周二下午，老师召集所有人碰头过初稿。

他从扉页一页页往后翻，拿红笔在纸上挑挑拣拣。仪器清单有两处型号要重新核实，时间进度定得有些盲目乐观，技术路线里有个步骤交代得含含糊糊。几位同学挨个解释自己的思路，我靠在椅子边上，暗自琢磨自己交上去的那部分会被红笔划掉多少。

老师翻到「研究背景与项目意义」，视线在纸上停了好一阵子，红笔悬在半空没落下。

「这一段是谁写的？」

「我。」我立刻坐直了身子。

「梳理得挺清晰。」他又顺着读了几段，「工程背景从哪儿来、为什么要在小型水槽做原型、想验证什么，逻辑是通顺的。前面几段不少地方还是材料硬贴材料，这一段至少能让外行顺着看明白。」

我心里刚微微一松，他手里的笔尖突然往其中一行一戳：「这里提到小型水槽内壁的声反射会影响到达时间差的估计精度，这是从哪篇参考资料里摘出来的？」

我迅速翻开笔记本，把提前标好的文献文件名和具体页码翻了出来。那篇论文正好带了一张多径反射的测线示意图，我把图例旁的文字指给他看，又老老实实补了一句：「具体会造成多大的时间差误差，我现在还没弄明白，只知道这是水槽实验里需要注意的问题。」

「嗯，吃不透的地方实话实说就好，别把设想写成铁板钉钉的定论。」老师点了点头，在旁边补了一笔「表述再收敛一些」，接着把稿子翻回前面，「其他几节也可以参照这个思路理，别光顾着往上堆生搬硬套的术语。」

他抬头看了我一眼：「你这块底稿打得扎实。等后面其他人改完，你顺便帮着把全篇的行文习惯和术语称谓拉齐一下，拿不准的技术细节随时找对应的同学对账。」

「行。」我应道。

碰头会继续往下走。我把批注一项项记在边栏，继续听学长们商量换能器选型和经费配比。那些深层硬件细节我完全插不上嘴，尤其听到多通道声卡采样的时钟抖动时，我连该从哪个角度提问都毫无头绪。

但翻到研究背景那一页时，几位同学已经开始对照我写的那部分修改各自的段落。

散会从实验楼出来，同行的一位学长在走廊抬手碰了碰我的胳膊：「你那部分写得是真顺畅，回头教教我怎么顺逻辑呗。」

我笑了一下，说其实改了好几遍，也借了 Atlas 帮着理框架。

「难怪。」他看了我一眼，忍不住咂咂嘴，「不过你那几篇参考论文标得是真严谨，我之前让 AI 帮着找文献，满嘴胡编乱造，害我白搜半天。」

我点点头，没多说什么。那些页码和图例确实是我一页页手翻出来的。

晚上回宿舍，我把申报书重新在屏幕上展开，先把老师圈出来的那句批注标红。共享盘里其他人的修改稿正陆陆续续往里传，整套材料渐渐有了个严整的雏形。

屏幕右下角还挂着一条 Epistemic Fellow 会员早已经过期的续费弹窗。我扫了一眼，顺手给叉掉了。眼下查资料、搭申报书框架，Atlas 免费额度已经完全够用；真等到以后需要动手写复杂代码做仿真时，再去挑性价比最高的工具也不迟。

我把批注好的新版本保存归档，扣上笔记本，端起饭盒往楼下食堂走。

项目最后能不能批下来还悬在半空。但看着那份申报书里终于有了自己踏踏实实码进去、而且能让课题组用得上的东西，走在晚风里，心里头还是觉得挺舒坦。
