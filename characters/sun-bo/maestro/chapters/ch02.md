<h3 align="center" style="font-family: Georgia; font-size: 1.125em;">Interlude 1 · September 2021</h3>

2021 年 9 月，几家主要 AI 厂商的通用模型已经各有侧重。OpenMind 的 ACT-4S 是当时的旗舰，能够处理文本、图像等多模态输入，响应速度快，也能胜任不少日常编程任务；成本更低的 ACT-4S Lite 则面向轻量、高频的使用场景。

Epistemic 的主力模型 Norbert-4 在代码生成、长文本理解和复杂指令执行上表现突出。上一代旗舰 Norbert-3 Apex 仍然在役，只是使用成本和等待时间都更高。Aleph 则维持着两条 Atlas-2 产品线：Horizon 以超长上下文和大规模材料分析见长，Swift 更注重速度与调用成本。长上下文并不意味着模型能够准确记住其中的每一处细节。

编程工具也在形成自己的生态。基于 VS Code 改造的 Caret 已经能够接入多家厂商的模型，同时提供自研的 Maestro。后者擅长基础补全、简单函数和局部代码修改，尚不足以稳定挑战一线编程模型；Caret 对文件的读取和修改，则依赖编辑器本身的功能，而不只是模型生成的文字。

这些模型各有所长，也都远未可靠到可以免去人工检查。对于大多数普通用户来说，选择哪一种，往往还取决于速度、价格，以及眼前究竟要解决什么问题。

<h3 align="center" style="font-family: Georgia; font-size: 1.125em;">Sec 1</h3>

九月下旬，宿舍楼下的树叶还是绿的。

我到未央大学已经有一阵子了。开学头几天，报到、领卡、搬行李、认教学楼，事情挤在一块儿，整天不是在排队就是在找地方。军训结束后开始正常上课，反倒有些不习惯早上七点多就得爬起来。

未央校区在市区，地方看着不算新。教学楼外墙被太阳晒得发白，路边的树倒长得挺高，到了中午，树荫底下总坐着几个拿外卖的学生。校门外面有小饭馆和文印店。跟招生网站上的照片比起来，真正的大学没那么讲究，路过宿舍楼时还能听见有人隔着窗户喊谁把晾着的衣服收一下。

我们住四人间，上床下桌。刚搬进去时，每个人桌上都堆着快递纸箱，电源插排从桌后面垂下来。现在差不多收拾好了，只有门背后贴的卫生值日表还没人认真执行。

晚饭过后，我端着从楼下买的酸奶回寝室，一进门就听见有人在抱怨电脑。

「这玩意儿为什么又打不开？」

靠门那张桌子的室友对着屏幕点了两下，随后把鼠标一扔。旁边有人戴着耳机打游戏，抽空瞥了一眼：「你上课不是跟着老师装过吗？」

「上课能开，回来就开不了了。」

我把酸奶放到桌上，拉开椅子坐下。自己的屏幕上也有个差不多的图标，是前几天程序设计课上跟着老师装的开发环境。

这学期有门《C 语言程序设计》。老师第一节课先让大家装软件，演示怎么新建文件、编译、运行。前两次上课讲的是变量、输入输出和条件判断。投影幕上代码一行一行往下写，我看着觉得还行，无非就是把数字读进来，再按条件算出结果。

但看懂别人写的东西，跟自己写出来，确实不是一回事。

下午老师在课程群里发了这周的作业，附件是个 PDF，里面有三道题。前两道分别是算两个数的结果、做简单判断。最后一道要读入三个整数，按从小到大的顺序输出，数字之间只留一个空格，末尾换行。

老师要求交源代码文件和运行截图，文件名得带学号，周五晚上截止。

我下午看完题目，觉得不算难，就没急着做。现在真打开开发环境，面对中间的空白编辑区，脑子里却只剩下一句老师上课反复讲的「先把问题拆开」。

怎么拆，我也没什么头绪。

我试着打了个 `#include <stdio.h>`，又凭记忆写了 `int main()`，敲出一对花括号。光标停在里面，半天没动。

旁边室友还在折腾软件，我倒不好意思过去问他。他现在连编辑器都没打开。

我索性切到浏览器。ActChat 的网址一直放在收藏夹里，点开就能进。暑假刚注册时还得想一想该问什么，现在反倒没那么犹豫了。

我把第三道题完整贴进去，后面加了一句：

「这是我们大一的 C 语言作业，我刚开始学，帮我写一个能运行的版本，尽量简单点。」

回答很快出来了。

它先说可以用临时变量交换数字，再给了一段完整的 C 程序。我顺着看了一遍，前面的头文件和 `main` 函数有点眼熟，后面是三段 `if`，每段里都有个 `temp` 来回倒腾。

我试着在脑子里过了一遍：先比前两个数，再比后两个，最后重新检查前两个。三个数应该就能排好了。

我把代码复制下来，回到开发环境，替换掉刚才敲的几行。点编译运行，底下弹出黑色窗口，等着我输入。

我敲了 `9 2 5`，按回车。

屏幕上出现：

`2 5 9`

「行啊。」我小声说。

我又试了 `3 3 1` 和 `-2 0 -5`，结果也都对。以前让我从头琢磨这三次比较，大概得翻半天书。现在从题目到程序跑起来，还没用上几分钟。

前两道题也差不多。ActChat 生成的都是短程序，我逐个复制、保存、运行。没出什么大岔子。

但第三道题折腾到后面，我又发现了个问题。

老师给的示例输出没有多余提示，程序只需要把三个数打出来。我让 ActChat 生成的那版，运行时却先显示了一行英文，叫我输入三个整数。

程序算得没错，可格式跟 PDF 里的不一样。

我切回网页，说：「别输出提示语，只按题目要求输出结果。」

它又给了一整段代码。

我把新版本复制回去，保存、运行。提示语没了，倒是我刚才自己加的一行注释也跟着没了。那行注释是我为了记住三次比较的顺序，对着程序慢慢写出来的。

我又回 ActChat 问能不能只改输出的地方。

它告诉我删掉某一行 `printf`，另一行保留。我挨个找，差点顺手删掉一个右括号。重新编译的时候下方冒出红字，我盯了半天才发现少了个符号。

「你写完了？」旁边有人站起来接水，路过我身后扫了一眼。

「差不多，改格式呢。」

「老师不是说源码和截图都要交吗？」

「知道。」

我把程序又运行了一遍，输出终于跟示例一样。明明就改了一个很小的地方，我却在网页和代码窗口之间切了好几轮。

<h3 align="center" style="font-family: Georgia; font-size: 1.125em;">Sec 2</h3>

这时候我忽然想起来，暑假不是还下载过一个写代码的软件吗？

Caret。

自从那天下午对着黑色工作区发愁，我就没再打开过它。后来用 ActChat 解决问题挺方便，那个编辑器早被我忘在脑后了。

我按下 Windows 键，搜出 Caret，点开。

熟悉的深灰色界面慢慢铺满屏幕。左边一排小图标，中间是空白区域，右侧挂着输入框。和暑假看到的差不多。

这次我倒知道 Open Folder 是干什么的了。

为了交作业，我之前在 D 盘建了个「C语言作业」文件夹，里面放着三个 `.c` 文件。我点开 Open Folder，选中它，左边的文件树立刻多出了几个名字。

我愣了两秒，点开第三道题。

中间终于不再空荡荡。刚才那段程序完整地出现在眼前，关键字变了颜色，左边还排着行号。

「哦，原来这样就行。」

我把鼠标挪到右侧输入框。本来想再把题目贴进去，可代码已经写好了，也没必要重来。我想了想，觉得自己写的那几行注释实在有点乱，要是它能直接帮我改清楚，倒正好试试。

我在输入框里敲：

「帮我把当前这个 C 文件里三次比较的注释写清楚一点，不要改代码逻辑，也不要添加输入提示。」

正要按回车，我注意到输入框下面有个模型菜单，当前显示 Maestro。

点开之后，几个熟悉又陌生的名字排在一起：Maestro、ACT-4S、Norbert-4，还有 Atlas。

旁边有一行小字：

「Third-party models may consume credits at a higher rate depending on the model and request size.」

我看了两遍，大概明白不同模型扣点不一定相同。有些请求可能会花得更多。

我顺手点开账户额度。第三方共享的一百点还在，Maestro 的两百点也没动过，跟暑假注册那天一模一样。

反正就是改几行注释，先试试送得多的那个。

我关掉菜单，留着 Maestro，再检查了一眼要求里写的「不要改逻辑」，按下发送。

侧边栏开始转圈。几秒后，一条回复跳出来，说为当前文件准备了修改。中间的代码区同时多了几块绿色和红色的标记。

我一时没反应过来。

仔细看，红色的是准备删掉的旧注释，绿色的是新写进去的文字。三段 `if` 一点没动，只是把我原来写的「比较一下」「交换」改成了更具体的说明。

底下还有接受和拒绝修改的按钮。

我把差异从上往下看了一遍。有几句注释是英文的，而且写得比我自己那版还绕。

我又在侧边栏补了一句：「注释用中文，简单点，我刚开始学 C。」

第二次给出的修改就顺眼多了。

我点了接受。

红绿标记消失，新的中文注释留在代码里。我把文件保存，又切回之前上课用的开发环境，重新打开同一个文件，发现注释果然已经变了。

原来它不是单独回我一段答案，而是真的把硬盘上的文件改掉了。

我按编译运行，把刚才用过的几组数字又输了一遍。输出还跟之前一样，没变。

不放心，我又在资源管理器里找到那个 `.c` 文件，用记事本打开了一次。里面确实就是刚才在 Caret 里接受的那一版注释。

靠门那位室友终于把他的开发环境弄好了，正趴在桌前对着代码敲敲打打。另一人问要不要去楼下买点吃的，他说等两分钟，程序刚跑起来。

我靠回椅背，把 Caret 的界面又看了一遍。

左边是我的文件，右边是聊天框，中间直接显示要改的地方。之前看别人演示时没觉得有什么特别，手头真有一份作业，才算弄明白一点。

当然，也就只是明白了这一点。

几段 `if` 我现在能看懂个大概，可真让我关掉网页从头写，八成还得卡住。以后要是碰上更复杂的题，我也不知道该怎么办。

不过，那两百点免费额度到底能干什么，现在总算有点概念了。

我把三个源代码文件按要求重命名，运行截图分别存好，再核对一遍文件名里的学号，没有急着把作业交上去。

这时屏幕右下角弹出 KOOK 的消息。

老周发来一句：「今晚来不来，阿杰说找到个地牢。」

我回：「作业刚弄完，等我上号。」

想了想，又切回 Caret 看了一眼。

Maestro 的额度少了一点，第三方共享的那一百点还原封不动地躺着。我没去研究到底怎么扣的，直接最小化窗口，打开 Minecraft 启动器。

宿舍里有人拆了袋薯片，塑料包装哗啦响了一阵。走廊外不知道谁喊了声去洗澡，紧跟着是一串拖鞋拍地的声音。

我戴上耳机，点进老周他们的 KOOK 语音频道。


<h3 align="center" style="font-family: Georgia; font-size: 1.125em;">Sec 3</h3>

刚连进 KOOK 语音，耳机里就传来阿杰和老周的嚷嚷声。

「你到底装没装对啊？服务端都重启两遍了。」

「我真按群里那个压缩包解压的，直接覆盖进去了！」老周那边的同学小林声音透着委屈，「点进服就弹红字，说模组版本不兼容，连接直接断了。」

老周叹了口气：「肯定还是 MOD 对不上。阿杰下午往服里加了什么，你本地肯定漏了东西。」

屏幕右下角的 Minecraft 已经挂在主界面。我切进群聊看了两眼，群文件里放着阿杰下午上传的「0921更新补丁.zip」，聊天记录里还有小林截的一张游戏报错图。

联机最怕碰上这种毛病。每次服务端动了配置，总有人因为少放或者多放了文件进不去服。以往遇到这种情况，解决办法笨得要命：要么让进不去的人把 `.minecraft/mods` 文件夹截成长图发在群里，几个人对着几十个名字又长又杂的 `.jar` 文件逐行肉眼挑错；要么干脆让人把整个客户端删了重新下一遍完整包。可宿舍这会儿正是用网高峰，几百兆的整合包下下来，半个晚上都过去了。

「你把 mods 文件夹截个图发群里我瞅瞅。」老周在麦克风里说。

「别截了，」小林发了个抓狂的表情包，「七十多个文件，我得截三张屏，字还小得看不清。」

我看着群里刷过去的几条消息，握着鼠标的手停在任务栏上。

两个人的 mods 文件夹，说白了无非是两份文件名单。找不同这种事，交给肉眼挨个排查实在折腾人。

我忽然想到了刚刚最小化的 Caret。

刚才它能在几秒钟里把 C 语言代码的文件读出来、直接把修改写进硬盘。既然它能对本地文件做操作，让它写个小程序来比对两个目录里的文件名，应该也不会太难。

大一的程序设计课才刚讲到分支判断，别说扫描磁盘目录，我连 C 语言怎么打开文件都还没学过。不过手头有 AI，我倒不需要自己把每一行代码从头琢磨出来，只要把要做的事说清楚就行。

我重新把 Caret 的窗口拉到前台。

输入框右下角还停在 Maestro 上。虽然菜单里挂着写代码口碑更好的 Norbert-4，但我账户里送的 Maestro 额度还有一大半。刚才改注释虽然多折腾了一轮，但基本要求都能跟上。眼前这种找文件的小需求，没必要动用昂贵的第三方额度。

我在右侧聊天框里敲下一段大白话：

「我现在有两个文件夹，里面存的都是 Minecraft 的 mod 文件。有人因为本地缺少或者多出文件导致无法进服。请帮我写一个简单的工具，能读取这两个目录，比较两边的文件名，并列出哪些文件缺少了、哪些文件是多出来的。」

按回车发出去后，侧边栏转了几秒钟。

Maestro 很快给出了回复。它建议用 Python 来写这个比对脚本，代码短，而且自带处理文件和目录的标准库。随着文字往下滚动，右侧直接生成了一份叫 `compare_mods.py` 的代码，底下还贴心列出了几行使用说明。

代码看着挺整齐，用了 `os.listdir` 获取文件名，再用集合的减法找出差集。

可代码给出来了，它并不会自己在电脑里跑起来。

我电脑里只有前几天刚装的 C 语言开发环境，根本没有配置过 Python。我试着在 Windows 终端里敲了个 `python`，屏幕上弹出了微软应用商店的安装引导。

我关掉商店窗口，按平时的习惯切到浏览器，去 Python 官网找了个 3.9 的安装包。下载、双击运行，安装时特意看了一眼教程常提醒的「Add Python to PATH」，把勾打上，一路点完。

回到终端重新敲了一次命令，黑底白字的交互提示符顺利弹了出来。

环境弄好了，我切回 Caret，在左侧的工程目录里新建了一个叫 `compare_mods.py` 的文件，把 Maestro 生成的代码直接放了进去，按 Ctrl+S 保存。

脚本写得很直接，顶部留了两个变量让我填待比较的路径。可阿杰下午发的是增量补丁，光拿它和完整的 mods 文件夹比较肯定不对。我在 KOOK 里问阿杰能不能给一份更新后的完整 mods 目录，又让小林把他现在的 mods 文件夹压缩发过来。两个压缩包下载完，我分别解压到临时目录，把路径填进脚本。

我在终端里输入命令，敲下回车。

屏幕上刷出一大片白字。

我凑近看了一眼，眉头皱了起来。终端打印出来的差异名单比我想象中长，连说明文件、备份包和禁用的 MOD 都混了进去，真正要找的那几个名字反而不显眼。

我顺着名单往下翻，很快发现了问题所在。

阿杰发来的目录里除了 `.jar` 文件，还夹杂着一个叫 `readme.txt` 的安装说明和 `config_backup.zip` 备份文件；小林那边也有几个后缀被改成 `.jar.disabled` 的禁用文件。脚本把目录里的所有东西全当成了 MOD 来比，那些格式不同的杂物直接搅乱了比对结果。

另外，阿杰更新包里的某些文件名带了小版本号的微调，脚本完全按字符串一字不差地核对，也把它们分别算成了缺失和多余。

不过版本号的事倒好办，肉眼扫一眼就能看出来。眼前最大的麻烦是那堆非 jar 文件的干扰。

我把终端里的几行输出复制下来，切回 Caret，在输入框里继续发：

「比对结果太乱了。请修改脚本：只扫描和比较以 .jar 结尾的文件，忽略其他所有后缀名；输出结果时，把『缺少的文件』和『多出的文件』分块显示，并在每块前面标出数量。」

Maestro 的反应很快。侧边栏给出了修改建议，把 `os.listdir` 换成了带条件过滤的列表推导式，增加了 `endswith('.jar')` 的判断，底下的打印格式也重新理了一遍。

它在 Caret 中间直接标出了绿色的新增代码。我点了接受，保存文件。

回到终端，按方向键上键调出上一条命令，重新回车。

这一次，跳动的光标停下后，终端里干干净净地吐出了两小排结果：

【缺少的文件 (2 个)】：
- xaeros_minimap_21.14.1_Fabric_1.17.1.jar
- voicechat-fabric-1.17.1-1.2.0.jar

【多出的文件 (1 个)】：
- xray-fabric-1.17.1-v1.0.jar

结果一下子清爽了。

我把这个脚本打包发给小林，在 KOOK 里跟他说：「小林，你在终端里跑一下这个脚本，把你本地 mods 路径和群里补丁包的路径填进去。」

「啊？我不会跑 Python 啊。」小林在语音里发愣。

「算了，我把结果发群里，你先核对一下。」我看着屏幕上的输出，「小地图和语音包这两个文件名，你那边没有；另外多了个 xray。光看名字还不能确定哪个导致进服失败，先按阿杰这次的更新清单把必需的文件和版本对齐。」

频道里安静了半分钟，随后传来鼠标快速点击的声音。

「卧槽……还真有！小地图被我放进新建文件夹了，语音包还是旧版。」小林翻了翻阿杰发的清单，「我先把这俩弄对，那个 xray 我也先挪出去，省得混着查。」

又折腾了几分钟，小林重新启动游戏。

伴随着一声清脆的进入游戏音效，左下角公屏弹出了提示：小林加入了服务器。

「进来了进来了！」小林在麦克风里喊了起来。

阿杰在语音里说：「可以啊孙博，至少一下子找到了几个该核对的文件。拿什么查的？」

「用 AI 帮我写了个比文件名的小脚本。」我随口应道。

「行啊，这比我们一个个找快多了。」老周接了一句。

我笑笑没接话，顺手把终端关掉，切回 Caret 看了看。

那份 `compare_mods.py` 还停在屏幕中间，满打满算三十多行代码。里面的几个语法细节如果让我离开 AI 自己手敲，我依然写不全，更谈不上什么系统掌握了开发。不过，刚才那堆文件名总算让它理出了头绪，最后到底是哪一个文件挡着进服，还得靠小林自己对照更新清单、重新试过才知道。

我把 Caret 最小化，戴正耳机，点进了服务器。

游戏画面加载出来，方块世界在眼前铺开，远处地牢的火把光亮隐约闪烁。


<h3 align="center" style="font-family: Georgia; font-size: 1.125em;">Sec 4</h3>

进入十一月下旬，西安的气温降得很快。

校道两旁的法桐叶子落了大半，清洁工每天清晨用竹扫帚把枯叶堆在路边。宿舍里的暖气片摸上去有了温乎气，水管偶尔发出咕噜咕噜的响声。开学那会儿的新鲜劲早被日常课业磨平了，高数、大物一门接着一门，周一到周五的生活被早八和晚自习填得满满当当。

《C 语言程序设计》也讲到了后半截。从最开始的简单分支和循环，一路学到了数组、指针、结构体以及文件的读写。

周三下午的课快结束时，老师在投影幕上放出了期末大作业的通知。

要求三人一组，自选题目完成一个带有交互菜单的综合管理系统，必须使用结构体和文件存储，两周后分批进行机房验收和答辩，同时提交源代码与课程设计报告。

投影幕上给了一串参考题目：学生成绩管理系统、图书借阅管理系统、小型进销存系统。

下课铃一响，教室里顿时嘈杂起来。前后桌的人纷纷转过头商量组队，我和同寝的室友陈鹏、隔壁班的林志顺理成章凑成了一组。陈鹏平时爱打游戏，动手实操快；林志平时上课做笔记极认真，期末想冲高绩点。大家一开始都想把这份大作业弄得漂亮点，没有谁想着糊弄。

三个人在食堂二楼找了张空桌，一边吃晚饭一边商量分工。

题目选了最常见的图书借阅管理系统。功能看似不复杂：录入新书、查询书籍、办理借还、显示所有库存，以及在退出程序时把数据保存到本地文件，下次打开能重新加载。

「我来写菜单界面和输入校验，最后的大作业报告我也能包一大半。」林志拿圆珠笔在草稿纸上列模块，「功能键选 1 到 5，输错了要提示重新输入。」

陈鹏咬着筷子说：「那文件读写交给我吧。存盘和读盘无非就是 `fopen`、`fprintf` 那几句，我以前在网上见过现成的例子，写起来快。」

「行，那我负责中间的逻辑，」我说，「查书、借书、还书的状态修改，还有图书结构体数组的维护。」

分工定得很顺当。林志在纸上随手写了个大概的字段，大家各自记下自己要写的函数名，约定好周末前把各自的代码写完，周六下午在寝室碰头合到一起。

接下来的几天，除了上课，我的空闲时间基本花在这个作业上。

我用结构体定义了书本的信息，编号、书名、作者，还有一个标记是否被借出的状态位。写具体逻辑时，遇到指针传参和字符串匹配的小疑问，我切到浏览器去 ActChat 问两句。比如怎么用 `strcmp` 实现按书名模糊查找，它给出的逻辑清楚直接，我顺着思路用 Caret 把函数写进本地的 `logic.c`。

自己单独用几条模拟数据测试时，借还状态切换正常，控制台打印也没报错。周五晚上收工时，我觉得这门大作业大概比想象中轻松。

可到了周六下午，三个人真把各自的文件拷到一台电脑上联调，场面一下子变了。

林志带了个 U 盘过来，把他的 `menu.c` 和陈鹏的 `file_io.c` 一起拖进我的工程文件夹。

我们把三个文件塞进一个项目里点编译，编译器下方瞬间爆出两排刺眼的红字。

第一道坎是跨文件的声明和接口。

林志在 `menu.c` 顶端直接定义了全局数组 `struct Book book_list[100]` 和计数变量，没有加 `extern` 声明，跟其他模块一链接就报了一串符号重复定义（multiple definition）；而在陈鹏的 `file_io.c` 里，他自己另起炉灶写了一份结构体声明，字段名用的是 `name`，没用我们商量好的 `title`。函数传参时指针类型直接对不上，编译器判定为不兼容类型，又报了一堆找不到成员的错误。

「你这字段名怎么跟我写的不一样？」林志指着屏幕问。

陈鹏挠了挠头：「我当时照着网上的存盘模板写的，顺手用了 `name`，没注意看纸上的记录。」

改结构体字段还不算最麻烦的。我们花半小时把公共的结构体定义抽出来，放进一个新建的 `book.h` 头文件，加上头文件保护宏，再用 `extern` 把全局变量声明理顺，各个函数的形参类型总算对齐，程序勉强能编译通过、跑出菜单。

可轮到测试保存和读取文件时，更隐蔽的毛病冒了出来。

我们在菜单里录入了两本书，一本叫《C程序设计》，另一本随手输了带英文的《Data Structure》。点击保存，屏幕提示保存成功，本地也确实生成了一个 `books.txt`。

但关掉程序重新打开、选择读取数据时，黑框框里的程序卡顿了两秒，随后刷出来的列表全乱了套：第二本书的书名只剩下一个「Data」，作者变成了「Structure」，后面的借阅状态没能成功解析成数字，读取循环由于没检查 `fscanf` 的返回值，直接卡在文件末尾死循环，控制台反复吐出同一行错误记录。

我打开那个 `books.txt` 看了一眼，陈鹏用的写入格式是简单的空格分隔：`fprintf(fp, "%d %s %s %d\n", ...)`。

问题就出在这几个空格上。

带空格的书名一存进去，`fscanf` 的 `%s` 遇到空格就提前截断。书名后半截的 `Structure` 被直接当成作者读了进来，原本的作者字符串去匹配 `%d` 失败，后续的所有字段跟着顺次错位。

寝室里安静下来。

林志有些着急地看了看手表：「周一早上第一节课就要交第一版进度检查，老师说要看基本运行效果。现在连存盘读盘都跑不通，报告里的运行截图根本截不出来。」

陈鹏把椅子往后挪了挪，神情有些尴尬：「我真没想到书名带空格会这样。我昨天自己测的时候，只输了数字和单个词，当时跑得挺好的。」

外面走廊上传来别人洗衣服和说话的声响，天色慢慢暗了下来。高数作业和近代史论文还压在桌角，大家手头都有别的事。

我看了一眼屏幕上被改得七零八落的代码。林志的菜单在等我们的函数，陈鹏的文件读写卡在解析格式上，而我写的查找逻辑一旦接上他们传过来的错位数据，也跟着报错。

「没事，大体功能其实都写出来了，就是接口和数据格式没对齐，」我把工程打包备份了一份，「你们先去忙别的，晚上我把这几个模块重新理一遍，顺便把文件读写的逻辑改掉。」

<h3 align="center" style="font-family: Georgia; font-size: 1.125em;">Sec 5</h3>

晚饭我和室友在二食堂吃了份大盘鸡拌面。回到宿舍时，天已经黑透了，窗外冷风呼呼刮着，走廊里弥漫着热水器烧水的动静和打游戏的叫喊声。

我拉开椅子坐下，拧开台灯，按开电脑。桌角放着半包纸巾和下午喝剩下的冰红茶，屏幕亮起，Caret 停在刚才打包备份的 `library_system` 目录上。

我把工程里的文件挨个点开：`book.h`、`menu.c`、`logic.c`、`file_io.c`。四个标签页在编辑器顶端排成一排。

下午三个人挤在一块儿改代码，七嘴八舌，越改越乱。现在屋里只有键盘敲击声，我把这几个文件从头到尾扫了一遍，问题逐渐清楚起来。

麻烦主要卡在两处。

一处是文件读写的格式。下午测试失败，根本原因在 `fscanf` 的读取机制上。用 `%s` 按空格截断，书名里一旦带空格，原本属于书名的单词被错当成作者读了进来，后面的借还状态跟着顺次错位，读取循环匹配不到正确的格式，直接在控制台吐出乱码。

另一处则是跨文件的接口。林志在 `menu.c` 顶上定义的全局变量，虽然加了 `extern`，但各个函数之间的参数传递依然混乱。我写的逻辑函数要求接收图书指针，林志调用的地方却传了下标，陈鹏那边的文件操作函数连返回值都没统一，有的写成 `void`，有的写成 `int`。

理清这几点，我习惯性地点开了 Caret 侧边栏的对话框。默认选中的还是 Maestro。

开学这两个月，我用 Maestro 补全过不少单文件里的排序和字符串处理，平时代币额度充足，用起来不用心疼。我把下午报错的信息整理了一下，敲进输入框：

「帮我把 `book.h` 里的结构体和函数声明统一，修正各个源文件的传参；另外把 `file_io.c` 的读写逻辑改掉，解决书名带空格导致读取错位的问题。」

回车敲下，Maestro 很快给出了响应。侧边栏刷出几段代码，并在右侧编辑区拉起绿色的修改建议。

我顺手点了接受，调出终端敲下编译命令。

屏幕下方依然蹦出了两行黄色和红色的提示。

我滑着滚轮看报错日志。Maestro 确实把 `file_io.c` 里的写入改成了制表符分隔，但在改写函数签名时，为了接收图书总数，把 `save_books_to_file` 的参数从两个扩展成了三个。然而由于它主要针对当前文件做局部修改，根本没有同步去改 `menu.c` 里的那处旧调用，编译器当场报了形参过少（too few arguments to function）。

我又在侧边栏追问了一句，让它把调用的地方对齐。Maestro 顺从地改了调用点，却转头在当前函数实现里顺手补了一句对全局数组的外部声明，结果和头文件里的声明再次发生符号冲突，链接器又是一片红字。

我停下手，揉了揉太阳穴。

这怪不得 Maestro。我自己给的提示词本来就简略含糊，而 Maestro 的长处在于当前文件的单点推断；面对跨着四个源文件到处牵扯的接口调用链，光靠在侧边栏丢一句模糊要求，它只能按眼前能看到的内容打补丁，自然顾了这头丢了那头。

我点开顶部的撤销历史，把刚才由 Maestro 改动的内容全部回滚，工程重新回到最开始的状态。

面对这几个相互牵扯的文件，我自己脑子里其实也只有一堆零散的报错，并不清楚多文件项目规范的架构该长什么样。

我切到浏览器，打开收藏夹里的 ActChat。这是我从暑假起就习惯用来请教思路的工具。我把下午遇到的符号重定义、参数对不上的困惑敲了进去：

「写 C 语言大作业分了四个文件，全局变量到处报重定义，函数传参老是对不上，这种多文件项目一般怎么设计接口才不容易打架？」

ActChat 很快给出了回复。它在回答里解释得清楚明了：初学者多文件项目最忌讳在各个源文件里到处声明或引用全局变量，极易引发链接冲突；标准的做法是由主函数持有图书数组和计数变量，头文件只放结构体定义和纯粹的函数原型声明，各模块函数一律通过结构体指针接收数据。至于文本存取，最好改用 `fgets` 按行读取，配合制表符拆分字段。

看着屏幕上的解释，我脑子里那团乱麻总算有了清晰的线索。

有了明确的架构方向，我新建了一个无标题文本，花了十几分钟把手头工程的现状和约束一条条理得明明白白：

第一，定义统一的 `Book` 结构体，字段只保留编号、书名、作者与借阅状态；去除全部全局数组，统一在 `main` 函数中维护图书列表，通过指针向各模块传递数据。
第二，规范 `book.h` 中的接口签名，声明所有的操作函数原型，包含明确的返回值，供 `menu.c`、`logic.c` 和 `file_io.c` 共享。
第三，重写文件读写模块，使用 `fgets` 按行处理，字段之间用制表符 `\t` 分隔，杜绝空格截断书名；读取时必须加入文件结束与解析防错。
第四，保证所有修改在四个文件中严格同步，不擅自更改函数命名。

理好这四条要求后，我再次看向 Caret 顶部的模型选择下拉菜单。

除了默认的 Maestro，菜单里还有 Epistemic 的 Norbert-4。

暑假刚注册时送的额度里，有专属 Maestro 的部分，也有供第三方模型调用的通用点数。Norbert-4 处理复杂长代码和多模块约束的能力在社区里口碑很好，但扣起调用点数来也相当快，平时写几行简单作业我根本舍不得选它。

现在手头有了清晰的架构要求和完整的四个文件上下文，正好试一试它。

我把模型切换为 Norbert-4，将整段整理好的要求连同四个文件的代码一起发送了出去。

生成状态栏亮起，Norbert-4 输出的速度比 Maestro 慢了半拍。

它先列出了一份四步改动的执行步骤，随后逐个文件给出了完整的修改内容。

从 `book.h` 的头文件防重复包含宏，到各个函数的参数类型，它给出的方案把下午遗留的混乱理顺了大半。全局变量被全部清理掉，改由指针传参，函数名完全保持了最初的约定，没有出现漏改或擅自改名的情况。

在处理文件存取时，它改用了 `fgets` 逐行读取文本，并用制表符拆分字段，避开了直接依赖 `%s` 带来的截断毛病。

我顺着它的思路，在 Caret 里逐个文件手动核对、修整，将改动合并进工程。

改完最后一个文件，保存。

我按下快捷键唤出终端，再次敲下编译命令。

光标闪动了一下，回车落地。终端里干干净净，没有半个警告，直接退回了命令提示符。

编译顺畅通过了。

我靠在椅背上缓了口气。但我心里清楚，黑框框能弹出来只代表语法对齐了，里面的数据到底能不能存住，还得靠实际输入说话。

我敲下运行命令，黑色的控制台窗口跳了出来。

林志写的菜单顺利打印在屏幕上：
1. 录入新书
2. 查询图书
3. 借阅图书
4. 归还图书
5. 保存数据并退出

我按下选项 `1`，开始按照下午踩雷的用例输入测试数据。

第一本，我输了编号 `1001`，书名《C Primer Plus》，作者《Stephen Prata》。
第二本，我特意挑了下午直接搞崩程序的带空格名字，编号 `1002`，书名《Data Structures and Algorithm Analysis》，作者《Mark Allen Weiss》。
第三本，随手输了一本《高等数学》。

三本书录入完毕，我又选了借阅功能，把编号 `1002` 的那本书状态改成了借出。

接着，我选了选项 `5`，屏幕上跳出一行「保存成功，程序已退出」。

我切到文件夹目录，用记事本直接打开刚生成的 `books.txt`。

文本里整整齐齐排着三行，字段之间用制表符隔开，《Data Structures and Algorithm Analysis》的完整名字安安稳稳躺在里面，末尾是标记为已借出的状态数字。

最关键的一步是读回。

我重新启动程序，在菜单里选择加载数据。

屏幕刷新，控制台刷出图书列表。三本书的名字一个字母没丢，后面的作者和借出状态也对得上。但在列表最底下，却突兀地多出了一行编号为 `0`、书名和作者全是一片空白的古怪记录，总记录数显示为 4。

我愣了一下，切回记事本看了一眼 `books.txt`。

三行数据底下，光标还能往下点一行。保存文件时末尾打了个换行，导致文件末尾留下了一个空行。

我立刻切到 `file_io.c` 看 Norbert-4 写的读取循环。问题一下子找到了：`fgets` 读到最后那行空回车时并未返回空指针，而是把单独的换行符当成有效行送进了解析流程，硬生生拼出了第四条空数据。

我顺手在读取循环的开头加了一行判断：如果当前行只包含换行符或空格，直接跳过。

改好后重新编译，再次运行程序并加载数据。这次多出来的空白记录不见了，列表清清爽爽停在三本书上。我又试着归还图书、查询不存在的编号，程序都正常弹出了提示，没有再出现下午卡死报错的动静。

测试全部跑顺，我长出了一口气。

看了一眼屏幕右下角的时间，已经快十一点半了。走廊上的水房已经熄了灯，寝室里陈鹏正戴着耳机赶工程制图的作业，林志在另一侧敲着近代史论文。

我把修好的代码打包成压缩包，在宿舍群里发了过去，顺带发了一条消息：

「接口和文件读写全理顺了，带空格的书名测试过了没问题。明天各自看看代码，周一早上带到机房。」

陈鹏摘下一边耳机回过头：「这就调通了？书名带空格不报错了？」

「按行读取重新分的字段，」我合上笔记本，「周一直接去机房合一下就行。」

周一早上的第一节课，机房里格外喧闹。

距离上课还有十几分钟，日光灯底下围了不少人，几个小组正聚在电脑前抓耳挠腮。有的屏幕上红字连成片，有的在反复重启黑框框。

我和林志、陈鹏早早占了靠窗的一排机位。

陈鹏昨晚赶完了制图作业，今早特意提前过来，在机房电脑上新建了几个包含特殊符号的书名测试样例，又特意去测了空文件和只读权限下的提示；林志昨晚赶论文赶到半夜，但也把菜单界面的排版做了一遍对齐，加上了输入非法数字时的防呆提示，顺便把第一阶段的实验进度表整理打印好。

上课铃打响后，任课老师背着手在机房的过道里巡视，逐组检查代码。

走到我们桌旁时，老师拉了张椅子坐下：「你们组谁主讲？演示一下图书录入和保存。」

林志坐在主控机前，熟练地打开编译好的程序，按顺序演示了图书录入、多词英文书名录入、借阅状态修改，随后退出程序，重新打开，当场把存盘数据读了出来。

整个过程顺畅稳定，终端里没有半点卡顿。

老师盯着屏幕上的数据列表看了一会儿，伸手拿过我们桌上的进度表，在考核栏划了一个勾。

「模块拆分和文件格式弄得还不错，没犯初学者直接拿空格拆字符串的低级错误，」老师把表递还给林志，「不过这只是第一阶段检查。后头还有两周时间，正式验收的时候，逾期罚款计算、模糊查找算法，还有动态数组扩容，都得补齐，别松劲。」

「好的老师，后续功能我们已经在列计划了。」林志忙不迭点头。

老师起身背着手走向下一组，后排立刻传来了别的组被指出内存泄漏的叹气声。

我们三个走出实验楼时，初冬的凉风迎面吹过来，林志和陈鹏在前面商量着中午去北门吃砂锅还是刀削面。

林志拍了拍手里的进度表：「总算把第一道坎跨过去了。接下来两周按部就班写，应该稳了。」

陈鹏也松了口气：「周末看那堆乱码，我还以为周一铁定要挨批。」

我插着兜走在后面，笑了笑，兜里的手机轻微震动了一下。

回到宿舍后，我打开电脑，随手看了一眼 Caret 的个人中心。刚才调用 Norbert-4 扣掉的点数已经结清，第三方通用额度缩减了一小截，看着让人有些肉疼。后面还有两周时间，老师提到的逾期计算、模糊查找和动态扩容，明显比这次搭框架更费劲；如果之后每次都大手大脚调 Norbert-4，那点赠送的点数肯定撑不到期末，平时写小函数还是得靠 Maestro，真遇到复杂接口才舍得用大模型。

我把周六晚上记着接口要求的那页草稿纸叠整齐，顺手夹进厚重的高数课本里。屏幕上的代码安安静静停在刚测通的版本，大作业的第一步算迈过去了，但真要让程序稳稳当当地跑起来，最后到底还是得靠自己一遍遍敲进去的测试数据。
