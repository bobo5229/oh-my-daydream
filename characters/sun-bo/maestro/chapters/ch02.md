十一月初的西安，气温降得很快。宿舍楼里还没到集中供暖的日子，瓷砖地面泛着一股湿冷的凉意。我从衣柜里翻出一件厚卫衣套上，拉链拉到领口，两只脚缩在棉拖鞋里。

大阶梯教室的多媒体讲台上，任课老师讲完指针那一节的内容，伸手关掉了PPT课件。投影幕布亮起，切出了一份带有教务处抬头的新文档——《C语言程序设计中期课程设计任务书》。

台下嗡嗡的窃窃私语声一下子散开。

老师用教鞭敲了敲讲台桌面，宣布了要求：每位学生独立完成，题目统一为“学生成绩管理系统”，两周后在机房现场验收。系统必须是基于控制台的交互程序，基本功能包括学生基本信息与多门成绩的录入、格式化浏览、按学号或姓名查询、计算各科平均分与总分、按成绩高低排序，以及最关键的一项——数据必须支持本地文件保存与重新加载，不能关掉窗口数据就丢。

验收时除了提交完整源码和简要设计说明，老师还会现场在键盘上敲几组极端测试数据，验证程序会不会闪退或者死循环。

散课回宿舍的路上，不少人都在唉声叹气。此前每周的OJ作业虽然也不轻松，但每道题的代码量撑死不过三五十行，输入输出都有严格样例，写完往网页上一贴，绿灯一亮就算交差。而这次的小课设不仅要写菜单循环，还要自己设计数据结构、处理文件读写与各种输入异常，明显上了一个台阶。

我倒没觉得有多慌。整个十月我都习惯了把网页端AI当作助手，既然每道小题都能顺利跑通，把几个功能拼在一起做个管理系统，想来也就是多写几个函数、套一层`switch-case`循环的事。

周六上午，我早早坐到书桌前，按开电脑，习惯性地把屏幕分成两半。左边是新建的工程文件夹，右边是浏览器的两个标签页：EpochChat和Norbert。

我顺手点开EpochChat，把任务书里的功能要点完整贴了进去，要求它生成一套大一水平的学生成绩管理系统C语言源码。

光标飞快下行，两分钟不到，一份近两百行的单文件源码完整吐了出来。结构体定义、主函数菜单、录入和展示功能一应俱全。

我把代码复制进本地的`main.c`，敲下`gcc`编译，终端顺利吐出可执行文件。在控制台里敲入数字1录入两名学生的信息，再敲数字2打印列表，屏幕上整齐地排出了学号、姓名和各科成绩。

一开始的进展顺利得超乎预期。但当我准备对照任务书补充细节时，麻烦接踵而至。

基础版本没有做防呆设计，如果成绩一栏不小心敲进负数或者超过一百的数字，程序照单全收；没有写修改与删除功能；最要紧的文件读写部分，AI给出的仅仅是用`fprintf`简单写入文本，只要遇到带空格的输入或者读取到空文件，程序就会在终端里莫名其妙地卡死。

为了补齐这些功能，我在`main.c`里反复修补。增加输入校验、补充文件解析、增加排序逻辑……单文件的行数很快突破了四百行。函数相互嵌套在一起，滚轮上下滑动翻找变量定义变得越来越费劲。

我想起老师上课时强调的代码工程规范，决定把工程拆成标准的多文件结构：`student.h`存放结构体定义与函数声明，`student.c`存放具体的功能实现，`main.c`只保留菜单调度与用户交互。

拆分的第一步就踩进了泥潭。

为了把总分和平均分字段放进结构体，我先改动了`student.h`里的定义；紧接着在`student.c`里改写计算函数时，参数类型顺手换成了浮点型；等回到`main.c`里调用时，传进去的实参指针又漏掉了一层取地址符。

按下保存，在终端输入`gcc main.c student.c -o score_system`，回车敲下去的一瞬间，终端里呼啦啦刷出两整屏刺眼的红色与黄色文字。

`conflicting types for 'calculate_average'`
`implicit declaration of function 'save_to_file'`
`undefined reference to 'delete_student'`

七八个报错叠在一起，行号在三个文件之间跳来跳去。

我皱起眉头，习惯性地复制了最后两行编译报错，切回浏览器贴给EpochChat。

EpochChat迅速给出了修正代码。我满怀希望地复制代码、覆盖进本地文件，再次执行编译。红字非但没有减少，反而冒出了新的警告——AI给出的补丁假设了另一个新的函数签名，它默认`save_to_file`接收的是文件名字符串，而我在头文件里声明的参数一直都是文件指针。

我赶紧又把`student.h`的内容全选复制，贴进聊天框说明当前上下文。AI道了歉，重新生成了一版实现代码。可当我把这段实现拷回`student.c`时，它之前帮忙写好的成绩排序逻辑又被覆盖掉了。

我坐在椅子上，鼠标在VS Code的三个标签页和浏览器的输入框之间来回切换，机械地复制、粘贴、保存、编译、报错、再复制。

半个小时过去，桌面上的三个源文件被改得七零八落。头文件里的声明、源文件里的实现和主函数的调用彻底脱了节。往往修好了文件读取的报错，排序函数又提示缺少声明；把排序函数的形参对齐，菜单调用处又因为变量名不匹配报错。

网页AI确实能写出正确的C语言逻辑，但它的视野始终锁在当前的网页对话框里。它看不见我本地硬盘上的文件树，不知道我刚才在另一个文件里改了哪个变量名，每次提问都需要我手动把关联的代码片段一点点搬运过去。一旦工程跨越了多个文件，这种靠人工搬运上下文的土办法不仅费劲，而且极其容易在反复覆盖中制造出新的破绽。

窗外的天色灰蒙蒙的，北风吹得窗玻璃微微发颤。我揉了揉发胀的太阳穴，靠在椅背上长长吁了一口气。

照这么折腾下去，光是把多文件的接口对齐，就得耗掉整个周末。

既然模型本身懂得语法和逻辑，市面上有没有什么工具，能直接读取我本地工程目录下的代码，自己跑编译排错？

我切出搜索引擎，敲进关键词：“AI 直接修改本地工程 C语言 代码助手”。

翻了几个技术论坛和开发者社区的讨论帖，满屏的讨论逐渐勾勒出专业圈子的工具生态。有人提到集成在编辑器里的AI插件，但在最新的几个高赞回答里，更多开发者在推荐一种不需要手动搬运代码的终端智能体——CLI Agent。

帖子里被反复提及的名字有两个：Epistemic旗下的**Kybernetes**，以及EpochAI刚推出不久的**Epoch Coder**。

技术贴里的描述看得很直观：这类工具直接运行在本地系统的终端里，赋予了执行终端命令和直接读写工作区文件的权限，底层配备了专门的工程Harness系统。遇到报错时，它能自己读取报错日志、定位涉事文件、规划跨文件修改并调用本地编译器验证，直到编译通过为止。

这正是眼下我最需要的东西。

我点开Epistemic的官方文档，顺着指引在终端里敲下安装命令。配置好环境变量与个人账号凭证后，我在终端把路径切到小课设所在的目录：

`cd ~/c_project/score_system`

随后敲下启动命令：

`kybernetes`

终端界面微闪了一下，原本单调的命令行提示符变成了一个带有状态栏与输入框的交互界面。Kybernetes迅速扫描了当前目录，清晰地列出了检测到的工程文件：`main.c`、`student.c`、`student.h`。

我在输入框里敲下一整段清晰的诉求：

“当前多文件编译失败。请检查 student.h、student.c 与 main.c，对齐所有函数的声明与实现签名，修复类型冲突与未定义引用，并在终端执行 gcc 编译命令，直到顺利生成可执行文件。”

回车键按下的那一刻，屏幕上的文字开始自动滚动。

终端里没有停下来等我投喂代码，而是自动显示出了一串连续的动作日志：它首先读取了`student.h`，提取出结构体定义和六个函数原型；紧接着读取了`student.c`，对比每一处实现的形参列表；随后定位出`calculate_average`的返回值在声明中为`double`、实现中误写成了`float`，以及`delete_student`在源文件中漏写了函数名。

日志飞快推进，随后屏幕上打出提示：“Applying changes to student.c... Applying changes to student.h...”

紧接着，它在终端底层自动调用了系统命令：

`gcc -Wall -g main.c student.c -o score_system`

光标闪烁了两秒，终端输出了清脆的返回结果：

`Command exited with code 0. Build successful.`

我几乎不敢相信，迅速切回到VS Code的编辑界面。

原本停留在屏幕上的红色波浪线全没了。打开`student.c`，接口声明与实现已经被规整地对齐，参数传递严丝合缝，文件末尾还特意补齐了此前漏掉的删除函数骨架。

不需要我在网页框和代码页之间来回复制，代码直接落在了我自己的硬盘上。那种把工程状态与修改闭环交给工具就地解决的顺畅感，把过去两小时手工搬运上下文的烦躁一扫而空。

借着Kybernetes搭建好的稳定架子，我顺势推进接下来的扩展功能。

我通过终端向它下达指令，让它在`student.c`里完善输入校验逻辑，要求成绩必须在0到100之间，输入非数字字符时主动清空输入缓冲区；随后又让它在保存文件时增加表头标记，方便下次启动时验证数据完整性。

工具在终端里有条不紊地读文件、打补丁、跑编译，我在本地负责执行可执行文件、手动输入测试用例验证功能是否符合预期。整个工作流的推进速度比单靠网页端快了数倍。

然而就在我打算让它继续优化排序算法时，终端界面忽然弹出一行醒目的黄色系统提示：

`Warning: Free tier quota limit reached. Please upgrade to Pro to continue.`

免费额度耗尽了。

我愣了一下，退出终端界面，顺着链接点开了Epistemic的账户后台。订阅页面上明确标注着费用：个人专业版每月大约20美元。

看着折算下来一百多块钱的数字，我握着鼠标迟疑了。大一每个月家里给的一千多块生活费扣掉伙食与零花，剩下的并不宽裕。为了一门大一上学期的期中小作业每月掏出一百多块，我实在下不去手。

我关掉网页，很快想起了技术帖里提到的另一款工具——EpochAI的**Epoch Coder**。

既然Epistemic的额度见底了，EpochAI那边肯定也有属于自己的新手试用配额。我熟练地打开终端，按照文档装上Epoch Coder，登录自己的EpochAI账号。

Epoch Coder默认搭载的是专门针对编程任务优化的GRM-4-Byte模型，同样以终端界面的形态展开工作。我把工程目录交由它接管，继续处理未完成的文件解析异常保护。

有了刚才额度突然耗尽的教训，我不再把所有的琐碎操作都扔给CLI Agent。

我迅速调整了分配策略：单函数的算法逻辑、格式化打印的具体语法、或者报错原因的解释，我依然切回免费网页端的EpochChat和Norbert去问，拿到现成的逻辑思路；只有在需要跨越`main.c`和`student.c`对齐接口、或者需要自动跑编译测试整体验收时，我才在终端里启动Epoch Coder敲入指令。

这种“网页端查零散疑难 + 终端Agent做跨文件落地与编译校验”的组合办法，最大限度地节省了有限的免费调用次数。直到整个学生成绩管理系统全部完工，两边的免费额度虽然都见底告急，但工程已经稳稳落了地。

十一月最后一周的周三下午，学院机房迎来了小课设现场验收。

机房里坐满了人，机箱风扇嗡嗡作响。前排几个平时不怎么调试的同学，在老师走过去时程序接连崩溃，有的因为数组越界在循环里闪退，有的因为读不到文件直接卡死在黑屏窗口。

轮到我的机位时，老师拖了张塑料圆凳坐到我身旁：“行了，跑一下吧。”

我点开编译好的可执行程序，黑底白字的控制台菜单清晰列出选项。

我按照操作指引依次演示：录入三名学生的真实数据，打印表格，各科平均分与总分整齐划一；执行按平均分降序排序，排位立刻重排；执行删除其中一名学生，列表实时更新。

随后老师倾身接过我的机械键盘，亲自敲下一组故意刁难的数据：在成绩栏里输入了一个120，随后又输了一个负五。程序没有闪退，屏幕上立刻弹出一行红色提示：“输入分值超出合法区间（0-100），请重新输入”，并重新退回等待输入状态。

老师微微扬了扬眉毛，又在键盘上键入保存命令，将数据存为本地文件，随后直接伸手关掉了控制台窗口。

“重新打开，把刚才存进去的数据读出来看看。”老师说。

我再次启动程序，按下读取数据选项。屏幕光标闪烁了一下，刚才录入的学生数据一条不漏地重新铺开，格式规整，完全没有乱码。

老师滑动滚轮看了看我放在VS Code里的三个源文件，靠在椅背上点了点头：“模块拆分做得挺规整，接口定义也算清楚。文件存取这里，你是怎么考虑多字段分割和文件结尾判断的？”

我没有慌乱，把自己这两周在调试中弄懂的细节平实地说了出来：结构体里如何按固定字段排列、`fprintf`写入时在每个字段之间加制表符标记、读取时如何用`feof`与返回值校验双重兜底防止最后一行空数据重复加载。

我只字未提终端里的Kybernetes和Epoch Coder，也没提两边见底的免费额度，只说了自己如何借助网页端AI学习文件IO函数、如何设计边界用例并在本地反复跑测试。

老师听完在成绩册的表格里勾了两笔，在本子上端正地写下一行评语，最后填上了成绩：93分。

“完成度很高，异常处理考虑得挺到位，继续保持。”老师拍了拍我的椅背，起身走向下一号机位。

机房窗外的初冬阳光斜斜洒在显示屏上，屏幕上的“93”分格外醒目。

我靠在椅子上，长长地吐出一口气，心里满是踏实的轻快。合上笔记本电脑，看着终端快捷方式图标，我心里清楚，写代码这件事不仅跨过了最初的门槛，而且那套摸索出来的工具组合与工作流，已经成了我手里最顺手的武器。
