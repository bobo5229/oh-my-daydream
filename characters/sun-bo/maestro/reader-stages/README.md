## 总体原则

## 开发权限与权威来源

1. `reader-design.md` 是**已确认产品共识**，Stage 文件描述执行组织，不得用阶段建议覆盖总纲。
2. 小说章节、`lore.md`、`worldview.md`、既有 Interlude 等仍是其各自 Canon 权威来源；阅读器工程不得擅自编辑它们。
3. 现有 Interlude 01、02、03 分别嵌于 `chapters/ch01.md`、`chapters/ch03.md`、`chapters/ch05.md`；其中 ch03 是**章节中途**，不能一概按「章首引文」处理。产品层解耦不等于必须物理拆源文件。
4. YAML 属于**阅读器展示／关联元数据**。章节时间、行业事件时间、Interlude 关联阶段和编年阅读顺序不是同一种字段。
5. 技术栈、YAML 精确字段、右侧抽屉拖动和左右抽屉同时展开等尚未确认；在相关 Task 启动前讨论。
6. 本项目只供作者私人阅读，不规划商业化、账号、评论或公开发布必要功能。

## 执行与提交规范

- **一次一个 Task**：Codex 指令用 `S00-T01` 这样的唯一 ID，限制允许修改的模块与交付物，禁止顺手推进下一个 Task。
- **先约束后实现**：先读取该 Stage 与 `reader-design.md`；遇到未决策方案，先提议并等待作者选择。
- **验收证据**：每个 Task 需要变更摘要、运行／构建步骤、测试或截图证据、未通过项与边界外事项声明。
- **状态管理**：`未启动 → 进行中 → 待验收 → 已验收`，必要时可标记 `阻塞`。目前一律为未启动。
- **阶段门禁**：只有本 Stage 的相关 Task 逐项通过验收，才评估进入下一 Stage；完成工作本身不代表作者已经验收。
- **小范围修复**：若发现跨阶段问题，记录为缺陷并说明影响；不得无授权修改其他阶段的内容。
- **只读回归**：验证构建不会改写小说原稿；识别不了的 Interlude 不得静默删除原文。
