## 阶段目标

验证阅读器可以在作者日常使用及原稿持续增加的情况下保持稳定。

**实施范围**：跨功能回归、阅读质量、可访问性、性能与维护交接。

**阶段外**：不继续无限扩展产品功能，不引入商业化与账号。

**全局约束**：只使用原有 Markdown 作为文本权威；不修改小说正文、Interlude、Lore、worldview 或 Canon。没有得到作者额外批准，不实现本 Task 之外的功能；必要时先提出具体变更供确认。

<a id="s07-t01"></a>

## S07-T01｜全功能端到端回归

- **依赖**：S04-T04、S05-T05、S06-T05。
- **输入／前提**：已完成的正文、双模式、抽屉、Lore 与图库。
- **修改边界**：仅测试用例、缺陷修复与被影响模块的局部回归。
- **只做这些**：覆盖首次进入／恢复位置、纯小说／完整编年、章中 Interlude、时间跟随暂停、Lore 搜索、图表放大与视图返回。
- **交付物**：关键用户旅程的可执行测试与问题清单。
- **验收标准**：主要路径无阻断问题；不存在跳错阶段、丢失段落和正文位置被覆盖。
- **明确不做**：不趁回归新增全新产品功能。

<a id="s07-t02"></a>

## S07-T02｜响应式可读性与无障碍

- **依赖**：S07-T01。
- **输入／前提**：全功能集成界面与常见屏幕尺寸。
- **修改边界**：仅样式、输入交互、语义／焦点等可访问性相关修正。
- **只做这些**：实测大屏与窄屏抽屉并排／覆盖切换、长文排版、主题对比度、键盘导航、关闭覆盖后的焦点返回。
- **交付物**：可读性／可访问性检查表与修复记录。
- **验收标准**：基本键盘操作完整，无焦点陷阱；正文不被挤到不可阅读且重要控件可操作。
- **明确不做**：不在本任务做未经确认的完整移动端重设计。

<a id="s07-t03"></a>

## S07-T03｜内容扩展与构建稳定性

- **依赖**：S07-T01。
- **输入／前提**：新增临时测试章节、错误 YAML、缺失图片与现有构建过程。
- **修改边界**：仅构建校验、资源错误恢复、必要缓存或性能修正。
- **只做这些**：验证新增／删除普通章节、更新索引、YAML 失配、资源缺失与内容锚点失效时的表现；检测无须改页面模板。
- **交付物**：构建报告、诊断示例、维护性测试。
- **验收标准**：正常新内容可按既定规则出现；异常不会静默丢弃原文或损坏旧进度。
- **明确不做**：不自动改写源内容来修复数据错误。

<a id="s07-t04"></a>

## S07-T04｜维护文档与最终验收

- **依赖**：S07-T02、S07-T03。
- **输入／前提**：各 Stage 的实现产物、测试和作者实际体验反馈。
- **修改边界**：仅运行／构建／数据维护／故障排查文档与必要的最后修复。
- **只做这些**：整理本地启动、内容增加、YAML 维护、资产增加、回归测试、问题回滚与后续迭代流程。
- **交付物**：用户操作简要说明、开发维护说明、验收报告及剩余候选需求清单。
- **验收标准**：作者可依据文档独立新增内容并确认构建结果；得到作者明确验收后才将 Stage 07 标为已验收。
- **明确不做**：不将未讨论的功能列为已完成，不代替作者做最终审美判断。

## Stage 完成条件

- [ ] 核心完整阅读路径、Interlude 时间线、Lore、图表和图库可连续使用
- [ ] 原始 Markdown 与 Canon 与阶段开发前相比未被不当修改
- [ ] 增加普通章节／档案／资源无需改组件模板
- [ ] 具备可靠的本地启动、构建、故障定位及维护文档
- [ ] 作者实际体验后明确验收，再决定是否进入长期优化

本 Stage 所有必需 Task 必须分别通过验收，并由作者检查整阶段结果。完成 Stage 不等于自动授权下一个 Stage。

如未决策事项影响当前 Task 的正确性，**先讨论形成明确选择，再下发该 Task 的 Codex 指令**，不得用候选方案冒充既定共识。
