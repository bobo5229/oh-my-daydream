## 阶段目标

先确立原稿只读与可靠解析的底座，为后续 UI 提供可复用的内容接口。

**实施范围**：内容盘点、技术方案决策、Markdown 解析、嵌入式 Interlude 无损提取、稳定内容标识及校验。

**阶段外**：不制作正式页面、Lore 搜索、完整编年阅读序列、图库或视觉动效。

**全局约束**：只使用原有 Markdown 作为文本权威；不修改小说正文、Interlude、Lore、worldview 或 Canon。没有得到作者额外批准，不实现本 Task 之外的功能；必要时先提出具体变更供确认。

## S00-T01｜现有内容与风险清单

- **依赖**：无。
- **输入／前提**：仓库现有 chapters、chapters-index、lore、worldview、图片／SVG 文件以及总纲。
- **修改边界**：仅新增阅读器工程的内容审计文档，不改原始内容。
- **只做这些**：清点章节与资料路径；标注已知嵌入式 Interlude 的位置和各类 Markdown 形态，记录空缺资源与构建风险。
- **交付物**：文件清单、数据流关系图或文字说明、嵌入式 Interlude 位置对照表。
- **验收标准**：每个已知章节可追溯到源路径；指出 ch01 开头、ch03 章中、ch05 开头的 Interlude；不臆造未来章节。
- **明确不做**：不初始化前端、不迁移文件、不建立正式 YAML 内容。

## S00-T02｜工程技术方案与位置确认

- **依赖**：S00-T01。
- **输入／前提**：审计结果、总纲以及维护／构建偏好。
- **修改边界**：仅设计决策记录与经批准的最小工程骨架（如作者明确授权创建）。
- **只做这些**：比较少量合理技术方案及解析依赖，描述只读内容来源、构建／运行机制与目录隔离，提交给作者选择。
- **交付物**：选型 ADR、可解释的依赖与目录方案、采用后的基础启动命令说明。
- **验收标准**：作者明确批准选型；不会让网站构建脚本写回小说目录；无多余服务端／数据库依赖。
- **明确不做**：不把候选框架写成既定事实；不制作业务功能。

## S00-T03｜只读 Markdown 内容接口

- **依赖**：S00-T02。
- **输入／前提**：已批准工程方案与审计中的实际 Markdown。
- **修改边界**：只涉及阅读器解析模块、派生数据类型与解析测试；源内容目录只读。
- **只做这些**：解析章节 Markdown，提供稳定章节 ID、标题、正文节点／HTML 等派生数据；覆盖标题、引文、强调、代码、图片；提供完整性诊断。
- **交付物**：可调用内容加载／解析接口、测试样本、运行命令。
- **验收标准**：能无损呈现至少现有章节常见语法；新增 Markdown 能通过统一接口读取，无需复制粘贴正文。
- **明确不做**：不开发时间线抽屉、不接入 Lore 搜索、不根据内容推断 Canon。

## S00-T04｜嵌入式 Interlude 无损识别

- **依赖**：S00-T03。
- **输入／前提**：已知 ch01／ch03／ch05 Markdown 与抽取边界定义。
- **修改边界**：仅扩展解析／派生视图与验证脚本。
- **只做这些**：从已有引用块安全生成 Interlude 派生条目与不丢失小说正文的分段视图；尤其支持章中 Interlude。遇到歧义时原样呈现并报告。
- **交付物**：识别规则、实际提取校验结果、源内容与派生视图的对应说明。
- **验收标准**：三处样本识别准确；普通引文不误识别；所有源文本均能归属到派生输出，没有重复与截断。
- **明确不做**：不拆改 Markdown，不直接决定双模式正式导航 UI。

## S00-T05｜内容契约与防回写验收

- **依赖**：S00-T03、S00-T04。
- **输入／前提**：解析接口、派生分段和真实章节索引。
- **修改边界**：仅接口契约、最小测试／构建说明和安全校验。
- **只做这些**：定义章节、派生 Interlude、源位置、稳定 ID 与失败状态的数据契约；补充原稿未修改校验与构建诊断。
- **交付物**：最小内容模型说明、单元／回归测试、Stage 01 可用的读取接口文档。
- **验收标准**：重建派生数据不需要修改原稿；能检测并报告失配；Stage 01 可独立消费章节数据。
- **明确不做**：不锁定未来 YAML 全字段，不实现展示层花活。

## Stage 完成条件

- [ ] 已明确并记录获作者批准的技术栈与项目位置
- [ ] 章节与三处已知 Interlude 可无损读取，任意普通引用块不会被误删
- [ ] 能通过 Git diff／校验结果证明源 Markdown 未改动
- [ ] 出现未知 Interlude 格式时安全回退并输出诊断

本 Stage 所有必需 Task 必须分别通过验收，并由作者检查整阶段结果。完成 Stage 不等于自动授权下一个 Stage。

- 稳定锚点与失败降级方案如何设计、如何测试

如未决策事项影响当前 Task 的正确性，**先讨论形成明确选择，再下发该 Task 的 Codex 指令**，不得用候选方案冒充既定共识。
