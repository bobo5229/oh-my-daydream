# 《总谱》后续剧情方向与技术叙事原则

> **定位**：第一学期后续的长期规划与候选故事库；不替代 `lore.md` 的技术时间线、`worldview.md` 的人物事实或 `beats.md` 的第一学期具体节拍。不代表相关章节已经完成。除明确标注已讨论确定的方向外，具体细节仍需逐步讨论。

## 一、成长机制（已确认方向）

孙博逐渐发现，前沿 AI 的能力远超自己接触的课程和初级代码难度。他从遇到作业问题才咨询 AI，转向主动高频交流、检索、让 Agent 尝试解决真实问题。发展差距应通过连续的兴趣驱动短故事表现：更快验证想法、踏入陌生技术、获得外部反馈，再积累下一次尝试的经验。其他同龄人也使用 AI；差距来自探索频率、实际参与和经验累积，不提前决定最终成就。

区分**自身独立掌握的知识**与**能够借助 AI 调动的工作能力**。能力可能远超理解深度，成长也可能不均衡；以行动和结果写，不要抽象宣告天赋或直接灌输技术理论。

## 二、2022 年寒假《方块纪元》开源贡献（ch04 已写）

> **状态**：以下是 ch04 已发生事实的摘要，不再是待写 Minecraft 方案。详细场景和最终措辞以最新 `chapters/ch04.md` 为准。

1. **架空游戏与生态**：孙博寒假玩方块沙盒 **Blockscape（《方块纪元》）** 的科技整合包。**Kinetica** 提供机械动力与漏斗、传送带；大型 GitHub 开源 Mod **Nexalogic** 提供工业加工与物流；**CoreLink** 是相关 Mod 使用的前置接口库。整合包与各 Mod 的独立仓库不是同一概念。
2. **故障与民间线索**：CoreLink 版本更新后，Kinetica 漏斗和 Nexalogic 管道在特定加载顺序、跨区块恢复场景下偶发停止传输；重放管道暂时恢复。孙博在贴吧/玩家论坛发帖求助，另一玩家报告同样现象并提供前置库更新线索。Norbert 协助设计备份环境、版本对照与最小复现，孙博亲自记录、录像和验证。
3. **技术因果**：旧 CoreLink 的冗余恢复通知偶然掩盖 Nexalogic 对第三方物品接口缓存失效与恢复处理不完整的缺陷；新版取消冗余通知，但保留正规的失效通知。Kybernetes 首次指导 `git clone` 大型 Java/Gradle 仓库，分析并修改 Nexalogic，构建本地实验包；孙博对 Java/Gradle 仍不熟练，负责玩家侧核实。
4. **Gulu 传播**：本地修复后，孙博在架空视频网站 **Gulu** 发布 AI 辅助修复、版本对照、实际测试过程的视频，附相关标签，获得五千多播放，未破万；明确只是未经官方审核的实验性版本，暂不公开分发改造的安装包。评论区先建议把代码上传 GitHub，后有了解开源协作的网友建议向官方仓库提 Issue、再考虑 PR。孙博据此向 Kybernetes 寻求操作指导。
5. **GitHub 协作**：首次系统地查重、提交经过事实核验的高质量 Issue；维护者复现并关联旧报告，邀请提交 PR。孙博在 Agent 指导下首次经历 Fork、分支、Commit、Push、PR；首版修复在高频传输路径有额外查询负担，随后因 Code Review、代码风格与 CI/加载顺序测试反馈多轮修改，在同一个 PR 上迭代。
6. **结局与认可**：修复最终合并，官方后续版本发布并在 Release Notes 感谢外部贡献者；孙博的用户名出现在 **Contributors** 列表中，但没有仓库写权限、Collaborator 或 Maintainer 身份。再次使用官方包验证工厂运行正常，随后回到游戏兴趣本身。

### 对后续章节的约束

- **首次项已用完**：不能再次把 Clone、Issue、Fork、Commit、Push、PR、首次 Code Review 和首次外部 PR 合并写成全新体验。参见 `character-growth-timeline.md`。
- **能力归属**：AI/Agent 承担主要复杂源码分析与实现，孙博主动求助、复现、事实核对、测试、对外沟通，并初步理解“本地能用不等于适合公共工程”；他没有因此独立掌握 Java、Gradle、Git 或成熟的软件工程设计。
- **公开分享的边界**：Gulu 视频是首次有实际社区反馈的玩家向技术分享，不等于长期经营技术频道或成为专业博主。
- **未锁定**：具体游戏/模组版本编号、仓库真实网址、维护者身份、未来是否再次投稿、后续开源贡献与社群关系。现有故事不应凭空扩展为正式研究履历。
- **用工具的原则**：2022 年 1 月后主力暂为 Norbert 网页端与 Kybernetes，但孙博会根据**实际可用的 SOTA、任务适配、成本和 Harness 体验**选择工具，而非效忠厂商；EpochAI/GRM 与 Aleph/Atlas 的存在和竞争主要由 `lore.md` 及合适的行业 Interlude 呈现，不为平衡曝光强行安排使用。

## 三、青年教师关系线（已确认起点，未来发展待定）

计算机学院年轻教师，授课是职业考核与职称发展的一部分，但教学认真且有热情；科研中较早拥抱 Vibe Coding、AI Agent/Harness，熟悉其工程能力。他在 2022 年 1 月课设验收时从 GUI 作品、源码风格、项目结构、学生回答等综合推测 Agent 深度参与，在公开场合不点破，不强逼解释课外实现。**教师不是通过代码风格神奇鉴定了具体产品。**

老师对孙博的兴趣不等于认定天才或立即招募科研人员；他提出课下单独聊聊，且 **ch03 已写出验收当天下午的办公室交流**：私下点破 Vibe Coding、区分工具能力与个人知识，并提出大创/萌创方向可供下学期了解。**尚未**加入项目或建立确定的长期科研关系；教师姓名、研究方向、下次互动与实际合作仍待定。

## 四、未来技术与行业 Interlude 的创作原则

- 故事时间超出现实已验证技术后，可以虚构新的实现与技术突破；重点保证**产业、研发、工具能力与后果之间的因果连续、自洽**。允许理论目前无法完整解释的未来能力，不用强迫每次突破都有现成论文背书，也不把“无法解释”写成魔法。
- AGI、AI 参与 AI 研发以及 RSI（递归自我改进）可成为未来演进路线，但**尚未锁定其出现日期、具体机制、发展速度或结果**。AI 研发反馈循环可能加速模型迭代，也要在叙事中呈现算力、验证、资源等实际条件及其变化。
- 模型迭代可以越来越快；并非每次更新都值得一篇 Interlude。行业篇记录重要模型发布、可观察能力与开放状态，人物篇用有钩子的真实任务承接能力变化；不强行让孙博体验每家产品。
- 已写的行业 Interlude：**2021 年 9 月**见 ch01；**2022 年 1 月**见 ch03。其他厂商 12 月至 1 月的迭代仍待讨论，不得为平衡戏份填充未经确认的发布。
- 新 Interlude 写作先依据最新 `lore.md` 和 `interlude-anti-defensive-writing.md`，现实对标只作为作者校准，不在架空新闻里直接出现真实模型名称。

### 早期技术编年史的叙述深度（已确认）

2021—2022 年初的 Interlude 以**正式发布、可观察能力变化、开放渠道、产业竞争格局与现实应用影响**为主。即使作者对模型技术进行内部校准，也不必为每次发布硬写模型结构、训练数据、优化算法、论文或虚构的精确榜单；不将缺少机制说明写成缺少因果。行业篇保有独立于孙博认知的客观视角，**不要求只叙述孙博已经知道的内容**；但随着人物真正接触 AI 研究和技术理解加深，后续可在有叙事价值时增加技术细节。

**Aleph 已确认的新模型方向**：2021 年 12 月发布 **Atlas III-Nova**（具体日待定），在世界知识、有效长上下文理解、文字创作和原生多模态理解方面达到第一梯队，部分任务领先，但尚未形成绝对优势；**2022 年 2 月发布 Atlas IV**（具体日待定，能力参考 Gemini 3.1 Pro），在科学研究辅助、世界知识、有效长上下文、文字创作与原生多模态方面确立明显领先，其中科学文献综合、跨学科研究、假设与实验方案分析显著优于同期 GRM、Norbert。两代专业 Coding 均具有实力，但复杂软件工程任务整体不如同期 GRM、Norbert 的顶尖型号。Atlas 长期侧重知识、创作与多模态而非争夺专业 Coding 第一；具体开放渠道、价格和技术细节尚未锁定。该模型已在第三章对应时间段的世界中存在，不代表孙博已经关注或使用。

**EpochAI 下一阶段已确认的世界线方向**：2022 年 2 月 GRM-4.1 综合能力跃居同期前沿模型首位，尤其在复杂推理、数学和高难度编程上明显领先；2022 年 3 月 GRM-4.1-Byte 在可比较的模型层面 Agent 编程评测中进一步建立明显优势，并接入 Epoch Coder。其他厂商在多模态、长上下文、语言风格或实际 Harness 工作流上仍有竞争力。两者是模型进步，不能据此断言 Epoch Coder 的 Harness 全面超过 Kybernetes。具体发布日期、算法机制、评测数据、定价，以及孙博是否/何时改用均未锁定。人物不会为了均衡厂商出场而强行试用 GRM、Norbert、Atlas；他会依据实际可用 SOTA、任务适合度、成本与工具体验选择。
