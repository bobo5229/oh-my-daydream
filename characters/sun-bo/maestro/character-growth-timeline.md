# 《总谱》｜孙博能力成长时间线与增量台账

> **定位**：跟踪主角在故事时间线上的**实际经历、能力增量、认知边界和未完成学习**，防止后续章节重复安排“第一次”、倒灌知识或把 AI/Agent 的能力误写成孙博自己的能力。
>
> **依据与优先级**：已写正文 `chapters/ch01.md`—`ch06.md` 是“已经发生的事”的直接证据；`worldview.md` 规定人物底色与认知边界；`lore.md` 规定同期技术可能性；`beats.md`、`future-arcs.md` 规定已确认方向与未写情节。若文件存在冲突，**记录冲突并复核，不自行改写 Canon**。
>
> **范围**：2021 年 9 月至 2022 年 4 月第六章结尾。日期若正文未精确确定，只记月/阶段；未写的后续科创实验与项目获批不得当作既成经历。
>
> **状态用语**：
> - **接触**：见过、听过、按指导做过；不能等同熟练掌握。
> - **辅助实践**：在网页 AI/Agent 指导下实际执行，能核对部分事实与结果。
> - **初步独立**：在类似简单情境下，可自己重复操作、判断与验证；不意味着能迁移到陌生大工程。
> - **熟练掌握**：需要多次跨情境、独立可靠表现；截至第六章，不轻易使用这一评级。
> - **候选增量**：尚未写进正文；不得标为“已获得”。

## 三、六个阶段的真实成长差异

1. **ch01：会用网页 AI 帮自己完成入门题，并开始自行验证。** 成长是建立最基础的编程反馈闭环，不是“第一次使用 AI”。
2. **ch02：发现上下文和工作区问题，第一次借助真正的 CLI Agent 维护多文件项目。** 成长是工具工作流改变，不是模型突然学会写 C。
3. **ch03：更敢提出自己未必会实现的功能与体验要求，亲眼看到 Agent 交付远超自己独立知识水平的成品。** 成长是可行动范围扩大和边界意识出现，不是瞬间成为 GUI 工程师。
4. **ch04：首次将 AI 辅助修复分享给玩家社区，从评论获得正式开源协作的线索；第一次接受维护者与 CI 的外部技术反馈，修正方案并获得真实开源贡献。** 成长是公开技术传播、复现证据、协作与工程质量意识的**新维度**；之前已有测试习惯，因此不是“第一次会测试”。

5. **ch05：主动寻求本专业的科创机会，将 Atlas IV 用于材料理解、申请书写作与来源核实，初次获得导师对文字组织与任务完成度的肯定。** 成长是正式团队材料交付与主动争取机会，不是已经学会专业科研。
6. **ch06：在真实实验室已有程序上完成局部维护与用户验收。** 成长是会描述实际问题、备份原程序、让 Encoder 帮忙找修改点和提出测试办法，再通过操作验证与学长验收完成交付；不是已经能独立编写严密的需求规范、设计回归测试或编排多 Agent。

## 四、后续写作的防重复机制

每规划一个新章节，先填以下五项，再决定它是否构成真正的成长：

| 必填项 | 应回答的问题 |
| --- | --- |
| 故事时间和既有水平 | 此时已发生哪些章节？人物可以自主做到什么？ |
| 新任务的现实触发 | 他为什么要做，而不是作者为什么要教学？ |
| 本章**净新增**的能力 | 比已完成章节多了哪一个可观察行为、判断标准或责任？ |
| 原有能力如何复用 | 哪些应自然熟悉、哪些仍需查资料和 Agent？ |
| 未掌握的边界 | 成功之后仍不会什么？后续哪种失败或新情境还合理？ |

**判定规则：**
- 如果“本章净新增”只能写成“又用了 Agent 修问题”“又写了 Issue/PR”“又被认可”，通常属于**旧能力复现**，可以作为铺垫，但不应当作主要成长高潮。
- 新**领域**不必自动等于新**能力**；要说明新复杂度、职责、协作对象或判断标准。
- **首次/第一次**只许在时间线上出现一次；后续可写“第一次独立完成”“第一次跨团队”“第一次在更高风险场景承担责任”，但要明确新的限定条件。
- 把“AI 完成了什么”“孙博实际做了什么”“他现在能独立做什么”分别写清。不能依据成品规模倒推个人水平。
- 外部验证的认可性质要区分：OJ/课程评分、维护者合并、真实用户采用、正式责任/权限不是同一层级。
- 若出现版本、日期或技术能力疑点，以最新 `lore.md` 核对；若正文与规划冲突，先标出、讨论，再修改。
- 每次写完章节，**更新本台账**：新增时间线行、更新能力维度、写明未掌握之处；对旧行只作事实勘误，不擅自将候选写成已发生。

## 六、维护说明

- **文件职责**：`chapters-index.md` 记录“发生了什么”；本文件记录“因此新获得了什么、还有什么不会”；`worldview.md` 记录稳定性格与人物事实；`lore.md` 记录世界技术事实。互相引用，不互相替代。
- **更新时机**：新增章节、重写关键情节或明确锁定某个成长节点后同步更新。
- **证据等级**：正文已表现的行为 > 经确认但尚未写入正文的方向 > 未确认提案。仅正文已表现或用户明确确认的成长事实才能进入“已获得”区。
- **重要提醒**：本台账是用于校验写作连续性的索引，不是新增剧情的授权；未来能力仍需以实际故事证明。
